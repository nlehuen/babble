# Babble Architecture

This document is the detailed architectural reference extracted from [AGENTS.md](../AGENTS.md) so `AGENTS.md` stays compact enough to avoid prompt truncation across agent harnesses. See [docs/design/README.md](design/README.md) for the index of all BIPs and the milestone roadmap.

The pipeline is: Babble source → parsed AST → analysis → tree-walking `Interpreter` *or* unified typed `HIR` compiler (`HirBuilder` → `PassManager` (`-O0`/`-O1`/`-O2`) → `HirEmitter` → ASM JVM bytecode *or* `WasmProgramLinker` → `WasmWriter` → WebAssembly 3.0 `.wasm`), with strict separation between the parsed AST, the HIR, and the backend code.

- **Grammar** (`src/main/antlr4/.../Babble.g4`): predicate-free LL(1)/LL(2) single-bracket `()` grammar with zero `@parser::members`, zero `@lexer::members`, and zero semantic predicates (`ParserGrammarTestCase` enforces this and verifies pure `PredictionMode.SLL` parsing across all `.ba` and `.batest.md` files). Everything is an `expression`, plus `BIP019`/`BIP030` structured `axiom Target: ...` declarations (`class notnull`, `fn ... : T!` / `fn ... (…): T!` inferred-effect axioms, and universal `T!` non-null type syntax alongside `T?`; `BIP027-D6` retired the legacy `axiom ... on ...` / `io on ...` rule and `on` keyword); labeled alternatives (`# defExpression`, `# call`, `# rangeExpression`, `# tryExpression`, `# throwExpression`, `# coreExceptionRef`, etc.) become the visitor methods. Visitor generation is on, listener off. String literals cover strictly single-line `"..."` (`BIP026-D1`), raw single-line `r"..."`, JEP 378 `"""..."""`, and raw multiline `r"""..."""` (`BIP026-D2`–`D3`, decoded and validated by `org.babblelang.parser.StringLiterals`, with `r` remaining an ordinary `ID`). Effect keywords (`axiom`, `io`, `volatile`, `mut`, `shared`, `unique`, `frozen`, `calling`, `pure`, `nothrow`, `idempotent`, `commutative`, `associative`, `monotone`, `injective`), core type keywords (including `exception`, `BIP028`, and `range`, `BIP031`), `record`, `type` (type aliases, `BIP023`), `overload` (`BIP021`), `forever` (acknowledges code that never ends, `BIP024`), `try`/`catch`/`finally`/`throw` (`BIP028`), `match`/`case` (`BIP038`), `mod` (`BIP031`, also allowed on `def mod = ...`), and `of` are real lexer tokens exempted after `.`/`?.` and in named call arguments via `memberName`.
  - Newlines are significant: `NL` tokens (with `;`) separate statements, and `NL*` is permitted only after continuation tokens (binary operators including `mod`, `//`, `..`, `..<`, `,`, `=` and the compound `+=`/`-=`/`*=`/`/=`/`//=`, `->`, `then`, `else`, `as`, `is`) and before a selector's `.` or `?.` (a line may start with `.` or `?.`; float/double literals require a leading digit).
  - Never between an expression and a following `(`, which would recreate the call/juxtaposition ambiguity, nor before a unary `-` (`# negate`, binding tighter than binary operators; a negated integer literal is folded, so `-2147483648` is an int), so `a` then `-b` on the next line are two expressions.
  - `ifExpr` is factored (`IF test THEN NL* block (NL* ELSE NL* (elseIf=ifExpr | elseBlock=block))?`), `as` binds above `*`/`/`/`//`/`mod`/`+`/`-`, `..`/`..<` bind below `+`/`-` and above comparisons, `is` takes a static `type` above comparisons, and `not` binds below comparisons/`is` and above `and`/`or`.
  - `BabbleScriptEngine.parse` runs `PredictionMode.SLL` first with `BailErrorStrategy`, falling back to `PredictionMode.LL` only on failure.
- **Engine entry point** (`org.babblelang.engine`, `org.babblelang.effects`): JSR-223 (`javax.script`) implementation. `BabbleScriptEngineFactory.INSTANCE` → `BabbleScriptEngine` (lexes/parses, runs the analysis, `Compilable`, plus compile-time host effect configuration: `allowAxioms`, `allowsAxioms`, `assumeEffects`, `assumeConstructorEffects`, `markIO`). `org.babblelang.effects` provides the public `Effect` enum and `@Pure`..`@IO` runtime annotations for host Java classes, constructors, methods, and parameters. `getMode()` picks `COMPILE` (`compiler.CompiledBabbleScript`, the default) or `INTERPRET` (`BabbleCompiledScript`) from the `babble.mode` engine attribute or system property.
  - The built-in "implicits" (`print`/`println`, `assert`, `import`, `same`, `classof`, the number conversions `int`/`double`, and the `java`/`javax` root packages; French aliases `affiche`/`afficherc`, `suppose`, `importe`) come from `runtime.Implicits.create()`.
  - `createRuntime(ScriptContext)` builds each eval's namespaces: implicits → `STDOUT` (`Implicits.withOutput`, the context writer) → script root (ENGINE_SCOPE bindings + top-level defs), and its `Modules` (the engine's `EvalModules`: the eval's loaded modules, compiled through the module cache).
- **Sessions and the REPL** (`docs/design/bip004_repl.md`): `BabbleSession` (`engine.newSession(context)`) evaluates successive inputs that see each other's definitions.
  - Each input that defines names is a scope *nested* in the previous one, in the analysis (`AnalysisSession`: chained file `ScopeNode`s, clean-completed scope tracking for `BIP034-D6`, type nodes, definition/occurrence scopes, and committed `RM002` callable/Java effect summaries the passes look up; `BlockScopes.analyze(file, session)` then `session.commit(analysis)`) and at runtime (a child `Namespace`; scripts run in a given namespace through `BabbleScript.eval(ScriptRuntime)`, the base class of both script kinds). So a redefinition shadows, earlier code keeps its definitions, and nothing static is weakened.
  - The session keeps one `Modules` for its lifetime, so a module imported by several inputs is loaded once. `BabbleSession.classify` tells `EMPTY`/`INCOMPLETE`/`COMPLETE` inputs apart from where the parser or lexer fails (`ParseFailure.atEnd`: unfinished `"""`/`r"""` blocks classify as `INCOMPLETE`, while unclosed single-line `"..."`/`r"..."` and malformed `"""abc` openings classify as `COMPLETE`).
  - `org.babblelang.Repl` is the loop on top: prompts, multi-line input, `:help`/`:type`/`:load`/`:cancel`/`:quit`, values shown (strings quoted), errors printed without ending the loop. `:type` is `BabbleSession.typeOf` (analysis without commit or run; `ScopeAnalysis.resultType()`, set by `TypeChecker.run` from the last statement and rendered as source syntax by `TypeDisplay`, which diagnostics don't use); `:load` is `BabbleSession.eval(source, path)`.
  - Lines come from an `org.babblelang.repl.LineSource` (BIP004 §9): `PlainInput` (pipes, tests) or `TerminalInput` (JLine, front end only: never in the runtime jar). `BabbleLineParser` makes Enter accept only inputs `classify` doesn't find incomplete, so multi-line inputs are edited and recalled whole; `Completions` (JLine-free, tested in `TerminalInputTestCase`) offers commands, names, keywords, `:load` paths and members after a chain of plain names, by lookups only, never calls. `Main.isTerminal()` uses `Console.isTerminal()` reflectively, since JDK 22+ returns a console for piped input. `org.babblelang.Main` is the command line: it runs a script as the first input of a session (`BabbleSession.eval(source, sourceName)`), binds `args` (`JavaObject.of(list)`), and starts the loop when there is no script or with `-keep-alive`.
  - Parsing is shared with `compile()` (`BabbleScriptEngine.parse`), which reports `Syntax error : unexpected …` with line and column; type diagnostics throw `TypeCheckException`.
- **Analysis** (`org.babblelang.analysis`): runs in both modes at `compile()` time, in four passes, in this order (`BlockScopes.analyze`):
  1. `BlockScopes` computes each scope's `def`s for hoisting, `axiom` declarations, and the members of classes, objects and interfaces (`TypeNode`), and checks placement (`return`, `this`, `super`, `private`, header `def`s, value-class rules, and forbidding escaping `return`/`break`/`continue` from `finally` blocks per `BIP028-D6`).
  2. `TypeChecks` resolves `implements`/`extends` statically (interface literals or Java interfaces), checks completeness, default conflicts, Java arities and `super`, and reports private/read-only access (including read-only catch parameters) when the receiver's class is statically known.
  3. `Resolver` (result: `ScopeAnalysis.resolution()`) binds every name to a frame `Variable` or to a runtime lookup; only the compiler uses it.
  4. `TypeChecker` + `EffectChecker` (`docs/design/bip003_type-system.md`, `docs/design/bip008_static-typing.md`, `docs/design/bip007_effects.md`, `docs/design/bip010_type-checker-simplification.md`, `docs/design/bip027_tackling-complexity-in-the-compiler.md`, `docs/design/bip028_exception-handling.md`) run static typing over `Type` (`any`, `byte`..`string`, `null`, nullable `T?`, union `A | B`, `TypeVar`, effect-annotated function types `Type.Function` with `EffectSet` and `mut`/`borrow` parameters, intersections of interfaces `A & B` (`Type.Intersection`, `BIP022`), arrays `array of T` (`Type.Array`, `BIP020`), nominal/parameterized class/interface instance types with `of` syntax, class values, modules, Java packages, Java classes and interfaces) using package-private collaborators (`BIP010` §7, `BIP027-I1`/`I3`–`I6`): `TypeAlgebra` + `TypeVariance` (polarity-based per-parameter covariance across Babble records/classes/interfaces and Java generics), `TypeAnnotations`, `ExpressionTyper`, `ExceptionTyper`, `CallableTyper`, `TypeCheckDiagnostics`, `MemberTypes` (including iterable resolution), `OperatorTypes`, `CallSolver` + `ConstructorCallSolver` + `OverloadCallResolver` + `CollectionCallChecker` + `JavaCallSolver`, `FieldInitAnalysis` (`BIP040` definite/single-assignment & delegation checking), `JavaTypeBridge` (sharing `Overloads.isMoreSpecific` with the runtime), `Narrowing` + `TypeEnv`, `MatchTyper` + ANTLR-free Maranget `MatchExhaustiveness` (`BIP038`), `SlotInference`, `TypedProgram`, `LoweringAnalyzer` + `DispatchTargetDeriver`, `StaticRefs`, `SyntaxText`, and `TypedModuleSummary`/`ImportedSummaries`. `EffectChecker` is split into thin AST adapters (`EffectModifiers`, `EffectBodyWalker`, `CallEffectAnalyzer`, `InitEffectAnalyzer`, `MatchEffectAnalyzer`, `TryEffectAnalyzer`, `EffectAstExtractors`, and `BranchValueJoins`, which demotes the `unique` owners an `if` / `match` / `try` / `break` value join may alias) plus AST-detached cores `Reachability` (depth-bounded `k = 3` multi-path `PathKey` widening, `BIP027-D5` prefix-overlap & collection/view projection `mut` exclusivity, and the shallow modality of a fresh local container : one `Provenance` of its elements, `BIP027-I5`), `JavaEffectResolver` (all `java.lang.reflect.*` and scoped redundant-axiom tracking), `EffectFixpointDriver` (Bourdoncle WTO), `SymbolicEffectSummary` (single-pass $O(k)$ intra-file and cross-module HOF instantiation with `BIP019` `readParams` forwarding), `ModalKindTable` (deep immutability by mode crossing, one cached kind per record, shared by the type and effect checkers), `Purity` (the OPAL-style lattice `JavaCallProfile` and `CallableSummary` share), `AlgebraicVerifier` (bounded E-graph equivalence reusing `org.babblelang.ir.egraph` + `AlgebraicRules` per `BIP027-D1` and the partial-derivative sign & bijectivity domain for `monotone`/`injective`, `BIP027-I6`), and `SizeChangeTermination` (polynomial-time Ben-Amram & Lee `[BAL07]` SCP termination over guarded integer decreases and acyclic `record` structural descent, paired with curated finite-collection `for`-loop `@TERMINATING` certification and `BIP027-D8` `Unused pure expression` enforcement). `HostEffects` lowers an engine's `assumeEffects` / `assumeConstructorEffects` / `markIO` registrations into an `AxiomData.AxiomTable`, which `JavaEffectResolver` consults after the program's own axioms (`BIP027-D6`). `TypeChecker.run` converges the slots, infers effects, re-converges once, then makes a single verification walk; expressions go through an explicit `typeOf(ctx, expected, role)` dispatch, and every `int`→`double` conversion is recorded by `coerce`. Features include generic call/constructor inference and covariance, call-site parameter inference (`BIP008-I7`) for non-exported/non-escaping/non-interface callables, inference for unannotated defs and members across their assignments via Tarjan lexical SCCs + monotone `SlotCell` worklist convergence, flow-sensitive narrowing (`is`, `else` subtraction, `== null`/`!= null`/`<> null`/truthiness, `while` loops), safe navigation `?.`, Bourdoncle WTO effect/algebraic inference & verification (`RM002` / `BIP007-I1`, `BIP016`, `BIP017`, `BIP019`, `BIP027-I3`–`I6`), `BIP028` `try`/`catch`/`finally`/`throw` checking (catch-type validation, redundancy/unreachability, `nothrow` restoration, dead-catch warnings, per-`try` `finallyNothrow` recording, and intra-procedural `activeTryStack` local-catch `@BORROWED` provenance), and diagnostics (`ScopeAnalysis.typeDiagnostics()`) worded like the runtime errors they predict.
  - Runtime checks (`BIP008-I5`–`I6b`): `TypeChecker` records `ScopeAnalysis.widensToDouble(ctx)` wherever `int` widens to `double` or `double?` (parameters, returns, `def`s, assignments, `if`/`while`/`try` joins) and records `ScopeAnalysis.checkedType(ctx)` for `as` casts and for Java generic calls/field reads whose reflection type is a `TypeVariable`/`WildcardType` resolving to a non-`any?` type (supporting `union`, `null`, `any`, and non-nullable `Builtin`/`FunctionType`/`JavaClassType`/`NominalType` with an id per class/interface expression: in a module, its key and the type's name, `lib/vec3.ba#Vec3`, stable across compilations; elsewhere JVM-unique, `T17`). `ClassShape` retains declared member and static types for `InterpretedInstance`/`BabbleObjects`/`BabbleType.setMember` (used by external Java writes and `any` writes), while Babble-side `this.x = …` direct field writes in `HirEmitter` omit checks. `JavaTypes.checkBoxed` (in `JavaMethod`, `JavaLinker`, `JavaClass`, `JavaDefaultCall`) rejects `null` for boxed primitive returns/fields (`Integer`, `Double`, `Boolean`), and `JavaTypes.checkParameters` (in `Faces`) checks arguments entering Babble from Java interfaces.
  - Results live in `ScopeAnalysis` via public sub-views (`lowering()`, `calls()`, `hierarchy()`, `effects()`; `BIP027-D3`, including `forEffects` for `HirExpr.For` `@TERMINATING` DCE and `tryFinallyNothrow` for `BIP028`) alongside top-level AST-detached `PrimitiveKind` and `LoweringTargets` (so `ir`/`opt`/`compiler` never import `ScopeAnalysis`, enforced by `ArchitectureBoundaryTestCase`). Non-typecheck warnings go to the context's error writer as `Warning : ...`, type diagnostics as `Error : ...`; errors become `ScriptException`s worded like runtime ones.
- **Modules** (`docs/design/bip005_modules.md`): `export def x = …` (top level of a file only, checked by `BlockScopes`; names in `ScopeAnalysis.exports()`) and `import("path.ba")`.
  - Loading: `ImportFunction` sends names ending in `.ba` to `BabbleScriptEngine.importModule`, which goes through the runtime's `Modules` to the engine's `EvalModules.load`. The engine's `ModuleSource` (*M4*, `docs/design/bip006_module-sources-and-aot.md` §4; the `babble.moduleSource` attribute, default `FileModuleSource.INSTANCE`; also `FileModuleSource.rooted(dir)`, `MapModuleSource`, `ClassPathModuleSource`, sharing `LogicalPaths` for `/`-separated paths) resolves the name from the importing module (a `ModuleId`: key + display name; the importer's source name maps back to it through `compiledAs`, else `ModuleSource.identify`, which for files accepts a `FILENAME` that does not exist).
  - Running: the module is compiled in the engine's mode and run once per eval on a `ScriptRuntime` of its own (own root namespace, same context and bindings, the eval's loaded modules keyed by `ModuleId.key`). The result is a `runtime.Module`: a read-only `HasMembers` view (plus `exportAt(int)` indexed access for `RM001`) of the exported names of that root, registered before the file runs so that cycles work. No backend has module-specific code: both script classes extend `BabbleScript` (`eval(ScriptRuntime)`, `exports()`).
  - *Static imports* (M2): pass 1 records each `import("….ba")` call with a string literal (`BlockScopes.imports`); after pass 1, `BlockScopes.analyze(…, ModuleLoader)` hands the file's `ModuleInterface` (exported names) to the loader (`started`, for cycles), then loads each import's interface (`load`; the engine's `Loader`, relative to the importing file), and `TypeChecks` resolves `implements`/`extends`/`super(I)` paths through modules (`resolveDefinition`, `moduleOf`, the exporter's `resolveExport`) and reports `No such export` / `Cannot assign to an export` (errors).
  - The module cache (`compiledModule`, under `moduleLock`) keys by `ModuleId.key` and keeps a module's compiled script and interface while the source, the mode and the version (`ModuleSource.version`; a content hash for files) of every module its analysis read are unchanged; runtime `import` goes through it too.
  - *Types across modules* (M3): a static import's type is `Type.Module`, whose members are the exporter's types; the `ModuleInterface` carries the exporter's AST-detached `TypedModuleSummary` once it ran (`typed`, read with `summary()`; `BlockScopes` keeps it as `pass.summary`, never the `TypeChecker`), so importers query lock-free exported types, declarations, members, and `CallableEffectTemplate`s without retaining the exporter's `TypeChecker`. Annotations naming a class through a module (`shapes.Circle`, or an alias of it) are nominal `Instance` types (`typeThroughModule`). Reading an export of a file still being analysed in an import cycle reports `Missing type : <name> (import cycle with <module>)`.
- **Block scope**: the file, function literals (parameters + body top level), and every other block (block expression, `if` branch, `while` body — fresh per iteration, `for` body, and `try`/`catch`/`finally` blocks) are scopes. Names a scope defines are declared (unset) on entry; reading or assigning them before their `def` runs fails with `Name used before definition`. Blocks that define nothing get no namespace. Top-level `def`s of class, object, interface and static bodies declare *members*, which bind no unqualified name (reading an uninitialized body member fails with `Member used before definition`).
- **Object model** (`docs/design/bip002_object-model.md`): `class (params) implements I ( body ) static ( … )`, `record`, `interface extends … ( … )`, `object implements … ( … )`, `this`, `super.m()`/`super(I).m()`, `x is T`, `private`, and the natives `same`/`classof`. Members are reached only as `this.x` or `obj.x`; `this.x` goes through `Members.selectOwn`/`assignOwn`, the only path that may see private members.
  - *Operator methods*: when the left operand of `+ - * / // mod`, or the operand of unary `-`, is a Babble object (`BabbleObjects.isBabbleObject`), the operator calls its public `plus`/`minus`/`times`/`div`/`floorDiv`/`mod`/`neg` (`Operators.method`, `Operators.NEGATE`; missing: `No such member : plus`). The interpreter does it in `visitBinaryOp`/`visitNegate` (`operatorCall`); compiled code evaluates both operands into locals, then branches on `BabbleObjects.isBabbleObject` to the same select and call `invokedynamic` sites `a.plus(b)` compiles to (`operatorCall`) when non-numeric, or lowers directly to JVM primitive instructions (including power-of-two `IAND`/`ISHR`/`LAND`/`LSHR` and non-negative-dividend `IREM`/`IDIV`/`LREM`/`LDIV` for `mod`/`//`, `BIP031`) when statically numeric (`RM001`). Both use `SyntaxText.operatorSite` for the call's messages. The type checker types it as that call when the left type is an `Instance`.
  - *Compound assignment* (`x op= v`, the `op` token of `# assignExpression`, `Operators.compound`) is `x = x op v` with the target read before `v` and an `obj.x` receiver evaluated once: the interpreter's `compound`, the compiler's `AssignAndMemberEmitter` (sharing `ControlAndOpEmitter` arithmetic), and the type checker's `compoundAssignment` (sharing `binaryOp`); the left operand's text in messages is `SyntaxText.targetText` (`x`, `obj.x`).
  - Runtime: `BabbleClass` (callable class value, statics, inherited defaults, `capturedFor` interface cells), `DynamicInstance` / `InterpretedInstance` (interpreter-only member array, `face()` `Proxy` cache, record equality/hash/`toString`), `BabbleObjects` (`ClassValue`-cached `$babble$*` metadata across plain compiled classes and `DynamicInstance`s), `ArraySupport` (runtime array creation, `size`/`get`/`set`, and interpreter side table of Babble element classes, `BIP020`), `ErrorFormat` (deep equality/hash/formatting and throwable messages), `Range` interface + `Ranges` factories + five Java `record` implementations (`IntRange`, `LongRange`, `CharRange`, `DoubleRange`, `ComparableRange`, `BIP031`), `BabbleInterface`, `ClassShape` (static description, string-encoded for compiled code), `Classes` (helpers both backends call), `Receivers` (branchless null-receiver checks), `BabbleConstants` (`java.base`-only `condy` constant bootstraps), `Supers`. Java boundary: `Values.fromJava`/`unwrap`, `Faces` + `FaceProxy` (`toJava`/`face`/`toJavaSam`, `Proxy` faces for interpreted instances implementing Java interfaces, and cached `LambdaMetafactory` factories for `0..16`-arg accessible functional interfaces with `Proxy` fallback for inaccessible/higher-arity SAMs), `Overloads`/`JavaTypes`.
- **Runtime boundary** (`docs/design/bip006_module-sources-and-aot.md` §3, §10): what a compiled program needs to run is `org.babblelang.runtime` and the built-ins of `engine.impl.natives` and `engine.impl.natives.java`.
  - `BabbleException`, `ThrownException` (wrapping thrown Babble nominal values), and `Throwables` (`sneakyThrow`, `unwrapReflection`, `toThrowable`, `unwrapForCatch`, `addSuppressed`, `matchesCatch`; `BIP028`) are in `runtime` too, so error messages start with `org.babblelang.runtime.BabbleException:` and Java exceptions propagate directly without per-call wrapping (`BIP028-D3`). The boundary references nothing of the front end (parser, analysis, ir, opt, compiler, interpreter, engine), no third-party library and no JDK module but `java.base`; `RuntimeBoundaryTestCase` enforces it by reading the class files' constant pools. `mvn package` also builds it alone as `babble-<version>-runtime.jar` (classifier `runtime`).
  - `import` reaches modules through the runtime interface `Modules` (`load(name, importerSourceName, rt)`), which the engine implements; `ScriptRuntime` is `(root, writer, modules)`, with no `javax.script`.
  - *babblec* (M5b): `compiler.Babblec.compile(main, root, jar, context[, optLevel[, debug]])` compiles through `BabbleScriptEngine.compileProgram(source, mainName)` (a `FileModuleSource.rooted(root)`, compile mode, with `BIP014-D2` AOT cross-module small-export inlining enabled at `-O1`+; the main module and every module its analysis read, as `ProgramModule`s) and writes a reproducible jar (sorted entries, fixed time stamps): the generated classes, the index `babble/modules.index` (`runtime.ProgramIndex`: main key, the root relative to the jar's directory, optional `implicitsClass`, and per-module key, display name, class, exports), the runtime classes copied from wherever `Launcher` was loaded, and `Main-Class: org.babblelang.runtime.Launcher`. When no compiled module contains a dynamic `import(expr)`, `RuntimeShaker` generates a minimal `babble/$Implicits` root-namespace factory (using `ModuleImportFunction` when no Java imports are present) and tree-shakes unreachable `org/babblelang/**` runtime classes via ASM constant-pool/bytecode reachability; programs with dynamic imports keep the full runtime automatically. Unless `-dbg` (`debug = true`) is passed, `RuntimeShaker.stripDebugLocals` strips `LocalVariableTable`/`LocalVariableTypeTable` from bundled runtime classes while preserving `LineNumberTable` and `SourceFile`.
  - The launcher runs the main class's `run(ScriptRuntime, Namespace)` with `args` bound and a `Modules` over the index, resolving import names from the importer's key with `runtime.LogicalPaths`; a module not in the index goes to a `runtime.ModuleCompiler` found through `ServiceLoader` (M5c: the full jar registers `compiler.FileModuleCompiler` in `src/main/resources/META-INF/services`, an engine per root compiling through `compileProgram`; the program's own modules stay the jar's at runtime), and without one fails with `a compiled program only has the modules it imports statically`.
- **Runtime** (`org.babblelang.runtime`, zero parser/front-end dependencies): everything both backends call — `Operators` (including floored `mod` and `floorDiv`), `MatchSupport` (`BIP038`), `Range`/`IntRange`/`LongRange`/`CharRange`/`DoubleRange`/`ComparableRange` (`BIP031`), `Truth`, `Members`, `Arguments` (the one implementation of argument binding), `Calls`, `Throwables`/`ThrownException`/`BabbleException`, the `Callable` calling convention `call(ScriptRuntime, Object[] args, String[] names, CallSite)`, `BabbleFunction`/`BoundMethod`, `CompiledFunction`/`FunctionBody`, `IntCell`/`DoubleCell`/`BoolCell`, `CallSite`/`OpSite` (source texts for error messages), `ScriptRuntime` (per-eval root namespace, output writer, `Modules`), and the scopes `Namespace`/`Scope`/`Slot`.
- **Interpreter** (`org.babblelang.engine.impl.Interpreter`): extends the generated `BabbleBaseVisitor<Object>`; one `visitX` method per grammar alternative. It tracks the `last` visited context so `BabbleCompiledScript` can report the line number on error (restoring `last` across `finally` blocks per `BIP028`). `return`, `break`, and `continue` use internal `ControlFlowSignal` subclasses (`ReturnException`, `BreakException`, `ContinueException`) that `visitTryExpression` never matches in user `catch` clauses while still running `finally` blocks (`BIP028-D4`). A self tail call (`BIP024`, marked by `analysis.TailCalls`, `ScopeAnalysis.isSelfTailCall`) returns a `TailCall` that `Function.invoke` runs as its next activation; the compiler lowers it to `HirExpr.SelfTailCall`, a jump back to the start of the method in `HirEmitter`, at every optimization level. `forever e` (`BIP024-D9`) is `e` in both backends. Class constructors are `InterpretedClassBody`.
- **IR, Optimizer & Compiler** (`org.babblelang.ir`, `org.babblelang.ir.hir`, `org.babblelang.ir.egraph`, `org.babblelang.opt`, `org.babblelang.opt.hir`, `org.babblelang.compiler`, `docs/design/bip001_bytecode-compiler.md`, `docs/design/bip014_optimization-passes.md`, `docs/design/bip027_tackling-complexity-in-the-compiler.md`, `docs/design/bip028_exception-handling.md`, `docs/design/bip029_batest-v2-and-ir-goldens.md`, `docs/design/bip031_ranges.md`, `docs/design/bip034_immutable-def-and-mutable-var.md`, `docs/design/bip039_mir-deorbitation.md`, `docs/design/bip042_egraph-pipeline-rewrites.md`): `BabbleCompiler` lowers the analysed parse tree via `HirBuilder` (coordinating `HirDeclLowerer`, `HirCallLowerer`, and `HirMatchLowerer` as the sole bridge from the parsed AST to HIR, followed by `HirNameInitAnalysis` for `BIP034-D6` definite-initialization annotation on `HirExpr.NameRead`, `HirNarrowAnnotator` for `HirExpr.Narrow` guard anchors, and `HirConvertMaterializer` for explicit `HirExpr.Convert`/`HirExpr.Widen` nodes per `BIP039`) into a self-contained `HirModule` (implementing `IrDumpable`; sealed `HirExpr` with `IrEffect`/`AliasClass`, `Narrow`, `Convert`, `Widen`, `Range`, `For` with `CountedRangeLoop`, `BinaryOp.MOD`/`FLOOR_DIV`, `Try`, `Throw`, `CoreExceptionRef`, `RecordNew`, `RecordReuse`, `Move`, and `Freeze`, plus `HirFunction`, `HirClass`, `HirInterface`, `ExprMeta`).   - Its methods: `run(ScriptRuntime, Namespace)` (split into `run$k` when large); per function literal, a direct entry point `fn$N$name` (`(self, thiz, rt, binder, Object p0, …)` — forwarding directly to `$spec` whenever specialized rather than duplicating the body), an optional `$spec` primitive-signature entry point (`fn$N$name$spec`) when any parameter or return is unboxed (`byte`..`char`), plus an `fn$N$name$call` array adapter (wrapped as `FunctionBody` via `LambdaMetafactory`; functions with more than 200 parameters only have the array form); one `cls$N$Name` (or `cls$N$Name$k` per `HirConstructor`) constructor wrapper per class/object expression (wrapped as `ClassBody`, returning the constructed instance and invoking a real JVM `<init>(BabbleClass, ScriptRuntime, <params...>)` directly when all `def` fields are final-safe so every header and body `def` field receives `ACC_FINAL` with zero `$defined$` bits, `BIP034-I5`/`BIP040-I3`), plus a direct static `$new(BabbleClass, ScriptRuntime, <prim...>)` factory on every capture-free, body-statement-free `fastRecord` (`BIP014-I4`); real JVM `interface` classes (`InterfaceGen`, `Script$N$iface$k$Name` / `babble/<module>$iface$k$Name`) with `bm$<name>` / `bm$<name>$spec` and JVM `default` methods (`RM003`); `CONSTANT_Dynamic` (`condy`) data constants via `BabbleConstants` and owner bootstraps (`CallSite`, `OpSite`, `ClassShape`, `Types`, `MatchSupport`); and static `CompiledMethod`/`OverloadSet` fields built in `<clinit>` helpers.

Each class/record/object expression gets its own plain JVM class `Script$N$k$Name extends java.lang.Object` (`BIP020-D18`: no runtime base class; `$babble$classStatic`, `$babble$class`, `$babble$rt`, per-class `equals`/`hashCode`/`toString`, and `$babble$javaDefaultLookup()` generated directly) implementing its Babble JVM interfaces (`bm$<name>` / `bm$<name>$spec` bridges + `$iface$<Id>`) and accessible Java interfaces (exact-signature Java overload bridges without `Proxy` allocation), with a field per member — `ACC_FINAL` on immutable header `def` fields of non-FBIP-reused records and classes initialized inside typed `<init>`, unboxed primitives for non-nullable primitive members, with an `int $defined` bitmask and `$babble$isDefined` when any unboxed body `def` may be read before init — methods as instance methods + optional `$spec` behind shared `CompiledMethod`s (a `fastRecord`'s methods get no instance field: `$new`, direct calls, bridges and `$babble$field` read the script class's per-class `CompiledMethod`/`OverloadSet` constant, and every class has a `$m$<name>()` accessor that cross-module calls and `SelectCache` go through, whatever the layout), and hidden `$v$x` fields for constructor variables methods capture; `this.x`/`this.m()` and statically resolved non-`this` / cross-module compiled class & `record` field/method accesses (`BIP014-I4`) compile directly to `GETFIELD`/`PUTFIELD`/`INVOKEVIRTUAL` (of `$spec` when typed and positional, else direct entry point).

Any other name read in a function or method body that is not namespace-scoped (a module's import, another class) is a `MutableCallSite` `invokedynamic` site bootstrapped by `Bootstrap.name` : its `NameCache` links a guarded `MethodHandles.constant` directly for initialized final `def` slots (`ns == cachedNs && Namespace.epoch() == cachedEpoch`, letting HotSpot C2 constant-fold functions/classes/modules), links direct `Slot.get()` for mutable `var` slots, and falls back past `MAX_DEPTH` distinct namespaces/epochs to a 1-entry `Resolution` cache (never caching uninitialized slots).

Where `TypeChecker` resolves a target statically, `RM001`/`RM003`/`BIP020` emit direct Babble `INVOKEINTERFACE` (`bm$<name>$spec`/`bm$<name>`), `INSTANCEOF`/`CHECKCAST` for `is`/`as`, `INVOKESPECIAL` for `super(I).m()` (with `$super$k` lambda-hoisting helpers), array `NEWARRAY`/`ANEWARRAY`/`ARRAYLENGTH`/`<X>ALOAD`/`<X>ASTORE`, Java `INVOKEVIRTUAL`/`INVOKESTATIC`/`INVOKEINTERFACE`, `NEW`, field `GET*`/`PUT*` (with `Values.unwrap`, `JavaTypes.checkBoxed`, direct `Throwable` propagation per `BIP028-D3`, and `Types.check` parity), and indexed `Module.exportAt(index)` reads without `invokedynamic` or `JavaLinker` overhead. Error lines come from the innermost stack frame of the script's classes with a line number (preserved on inlined and LICM-hoisted nodes per `BIP014-D5`).
- **Scoping** (`runtime` package): `Scope<T>` interface with `Slot` holders (`set` initialises, `assign` requires the slot to be set); `Namespace` is the main implementation (`child`, `declare`, `initialize`, `assign`, `lookup`). - **Natives**: built-ins implement `runtime.Callable`.
  - Native functions live in `impl.natives`: `print` writes to the `ScriptContext` writer, or `to:` any `Appendable`; `same`; `classof`; `ConvertFunction`, `int(x)` truncating towards zero and failing out of range, `double(x)`, both parsing strings, typed `int`/`double` by `TypeChecker.implicitType`; `CoreCollections` (`array`, `list`..`entry`, plus pure-`java.base` `listReuseOrCopy`/`setReuseOrCopy`/`mapReuseOrCopy` for `BIP014-I4` FBIP collection reuse).
  - Java interop lives in `impl.natives.java`: `JavaPackage` → `JavaClass` (a `JavaType`, equal by `Class`; members are public member classes, methods, then public fields: static final ones cached as constants, others read on each selection and never cached by `Bootstrap`, `isConstant`; instance fields only through an instance, `value(receiver, name)`; `assign` writes a public non-final field, `Members.assign` sending Java targets there, and refuses a Babble function for a functional-interface field, which needs `Runnable(f)` since member assignment has no `ScriptRuntime`) → `JavaMethod`/`BoundJavaMethod`/`JavaObject` (a `JavaValue` wrapper for objects Babble constructs, printing as its value; `JavaMethod` checks `JavaTypes.checkBoxed` outside its invocation `try/catch` so `BabbleException` errors are not double-wrapped).
  - Java calls return objects unwrapped; `Members.select` gives any Java object other than Babble's own values (null, boxed primitives, `String`, callables) its members through `JavaObject.member` (and arrays `size`/`get`/`set`/`equals`/`hashCode`/`toString` via `ArraySupport`), and `Overloads.resolveMethod` calls a method of an inaccessible class (`List.of()`'s) through the accessible type it comes from (`JavaTypes.accessible`). The type checker types a Java result or static field as `JavaInstance` of its accessible class (`any` for `Object` or when no accessible type exists), and arrays as `Type.Array` (`array of T`). Calling a functional interface's class with one Babble function converts it explicitly.
- **WebAssembly 3.0 backend** (`org.babblelang.wasm`, `docs/design/bip025_compile-to-wasm.md`, `BIP025-I0`–`I5`): whole-program AOT compilation directly from target-neutral structured `HIR` (`CompilationTarget.WASM_JS` / `WASM_BARE`, skipping JVM-only `FbipReusePass` `RecordReuse` so WasmGC `record` fields stay strictly immutable per `BIP025-D11`; `BIP034` header `def` fields of regular classes are immutable too, `BIP034-I5` value-captures are stored unboxed without `$Cell`s, and `BIP034-D6` definitely-initialized `NameRead`s skip `$UNDEFINED` checks, fold constant top-level/`static` `def`s, and read primitive top-level `def`s from unboxed globals) to WebAssembly 3.0 (`WasmGC`, typed function references, `try_table`/`exnref`, `return_call`) with zero new Maven dependencies (`BIP025-D2`).

- **Formatter** (`org.babblelang.format.Formatter`, command line `-format`, `org.babblelang.Babblefmt`): works on the token stream, comments included (the lexer puts them on the hidden channel, so the parser never sees them; anything counting tokens must look at the channel, as `BabbleSession.classify` does).
  - It reads in the parse tree (`BabbleScriptEngine.parseSource`) what each token is: a call's `(` or a block's, a newline that separates expressions (`sep`), continues one (+1 indent), sits in a parenthesised list, or precedes a block/`else`/`static` (dropped unless a comment is in the way). It keeps the source's line breaks otherwise; indentation comes from a stack of open parentheses, each anchored to the line where its `if`/function/class starts. Multiline `"""..."""` and `r"""..."""` blocks canonicalize `minIndent` to `(line.indent + 1) * 4` spaces (preserving `oldMinIndent` when a participating line has an intentional extra leading tab), strip trailing horizontal whitespace, and emit blank lines as `""`.
  - The result is parsed again and must give the same tree, newlines and semicolons aside (`shape()` normalizes multiline string tokens by `StringLiterals.decode` so canonical re-indentation passes while content drift fails with `IllegalStateException`). Note that `;;( … ;;)` closed on its line and followed by code lexes as a line comment (longest match).
- **`.batest.md` core & `-crib` HTTP runner** (`org.babblelang.batest`, `org.babblelang.crib`, command line `-crib`, `docs/design/bip041_crib-server.md`): the JUnit-free `.batest.md` parser (`BatestParser` / `BatestV2Parser` with `ParseOptions.STRICT` and `RELAXED`), runner (`BatestRunner`), filter (`BatestFilter`), and IR assertion checker (`IrAssertionChecker`) live in `org.babblelang.batest` (strictly outside `org.babblelang.runtime`) and are shared by both `BatestTestCase`/`WasmBatestTestCase` and `-crib`. `CribServer` (using JDK's built-in `jdk.httpserver`, zero new dependencies) serves loopback `POST /crib?<options>`, `GET /health`, and `POST /recycle`, dispatching trials to a warm pool of `CribWorkerMain` JVM subprocesses (`CribWorkerPool`) over dedicated-FD NDJSON IPC (immune to user `System.out`/`System.err` writes). Inside each worker, `CribEvaluator` runs each `(case, mode)` (`interpret`, `O0`, `O1`, `O2`, optional `wasm-O1`/`wasm-O2` via bounded-cache `WasmExecWorker`) in a fresh `BabbleScriptEngine` + `MapModuleSource` + child `ThreadGroup` with per-engine `BabbleCompiler.resolveVerify(engine)`, cooperative `ExecutionInterruptedError` interruption in `Interpreter`/`Function` loops, automatic cross-mode parity diffing, and post-trial JVM poison auditing (`System.getProperties()`, `Locale`, `TimeZone`, `System.out`/`System.err` identities, stray threads, heap watermark), with hard `Process.destroyForcibly()` + async respawn on hang, crash, `System.exit`, or poison.
