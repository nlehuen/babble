# Babble Architecture

This document is the detailed architectural reference extracted from [AGENTS.md](../AGENTS.md) so `AGENTS.md` stays compact enough to avoid prompt truncation across agent harnesses. See [docs/design/README.md](design/README.md) for the index of all BIPs and the milestone roadmap.

The pipeline is: Babble source → ANTLR4 parse tree → analysis → tree-walking `Interpreter` (on ANTLR `ParserRuleContext` directly) *or* ANTLR-free `HIR` compiler (`HirBuilder` → `PassManager` → `HirEmitter` → ASM JVM bytecode).

- **Grammar** (`src/main/antlr4/.../Babble.g4`): predicate-free LL(1)/LL(2) single-bracket `()` grammar with zero `@parser::members`, zero `@lexer::members`, and zero semantic predicates (`ParserGrammarTestCase` enforces this and verifies pure `PredictionMode.SLL` parsing across all `.ba` and `.batest` files). Everything is an `expression`, plus top-level/block `effectDeclaration` (`axiom`/`impure ... on ...`) rules; labeled alternatives (`# defExpression`, `# call`, etc.) become the visitor methods. Visitor generation is on, listener off. String literals cover strictly single-line `"..."` (`BIP026-D1`), raw single-line `r"..."`, JEP 378 `"""..."""`, and raw multiline `r"""..."""` (`BIP026-D2`–`D3`, decoded and validated by `org.babblelang.parser.StringLiterals`, with `r` remaining an ordinary `ID`). Effect keywords (`axiom`, `impure`, `pure`, `hermetic`, `mut`, `borrow`, `deterministic`, `nothrow`, `idempotent`, `commutative`, `associative`, `monotone`, `injective`), core type keywords, `record`, `type` (type aliases, `BIP023`), `overload` (`BIP021`), `forever` (acknowledges code that never ends, `BIP024`), and `of` are real lexer tokens exempted after `.`/`?.` in `memberName`.
  - Newlines are significant: `NL` tokens (with `;`) separate statements, and `NL*` is permitted only after continuation tokens (binary operators, `,`, `=` and the compound `+=`/`-=`/`*=`/`/=`, `->`, `then`, `else`, `as`, `is`) and before a selector's `.` or `?.` (a line may start with `.` or `?.`; float/double literals require a leading digit).
  - Never between an expression and a following `(`, which would recreate the call/juxtaposition ambiguity, nor before a unary `-` (`# negate`, binding tighter than binary operators; a negated integer literal is folded, so `-2147483648` is an int), so `a` then `-b` on the next line are two expressions.
  - `ifExpr` is factored (`IF test THEN NL* block (NL* ELSE NL* (elseIf=ifExpr | elseBlock=block))?`), `as` binds above `*`/`+`, `is` takes a static `type` above comparisons, and `not` binds below comparisons/`is` and above `and`/`or`.
  - `BabbleScriptEngine.parse` runs `PredictionMode.SLL` first with `BailErrorStrategy`, falling back to `PredictionMode.LL` only on failure.
- **Engine entry point** (`org.babblelang.engine`, `org.babblelang.effects`): JSR-223 (`javax.script`) implementation. `BabbleScriptEngineFactory.INSTANCE` → `BabbleScriptEngine` (lexes/parses, runs the analysis, `Compilable`, plus compile-time host effect configuration: `allowAxioms`, `allowsAxioms`, `assumeEffects`, `assumeConstructorEffects`, `markImpure`). `org.babblelang.effects` provides the public `Effect` enum and `@Pure`..`@Impure` runtime annotations for host Java classes, constructors, methods, and parameters. `getMode()` picks `COMPILE` (`compiler.CompiledBabbleScript`, the default) or `INTERPRET` (`BabbleCompiledScript`) from the `babble.mode` engine attribute or system property.
  - The built-in "implicits" (`print`/`println`, `assert`, `import`, `same`, `classof`, the number conversions `int`/`double`, and the `java`/`javax` root packages; French aliases `affiche`/`afficherc`, `suppose`, `importe`) come from `runtime.Implicits.create()`.
  - `createRuntime(ScriptContext)` builds each eval's namespaces: implicits → `STDOUT` (`Implicits.withOutput`, the context writer) → script root (ENGINE_SCOPE bindings + top-level defs), and its `Modules` (the engine's `EvalModules`: the eval's loaded modules, compiled through the module cache).
- **Sessions and the REPL** (`docs/design/bip004_repl.md`): `BabbleSession` (`engine.newSession(context)`) evaluates successive inputs that see each other's definitions.
  - Each input that defines names is a scope *nested* in the previous one, in the analysis (`AnalysisSession`: chained file `ScopeNode`s, plus the type nodes, definition/occurrence scopes, reassigned defs, and committed `RM002` callable/Java effect summaries the passes look up; `BlockScopes.analyze(file, session)` then `session.commit(analysis)`) and at runtime (a child `Namespace`; scripts run in a given namespace through `BabbleScript.eval(ScriptRuntime)`, the base class of both script kinds). So a redefinition shadows, earlier code keeps its definitions, and nothing static is weakened.
  - The session keeps one `Modules` for its lifetime, so a module imported by several inputs is loaded once. `BabbleSession.classify` tells `EMPTY`/`INCOMPLETE`/`COMPLETE` inputs apart from where the parser or lexer fails (`ParseFailure.atEnd`: unfinished `"""`/`r"""` blocks classify as `INCOMPLETE`, while unclosed single-line `"..."`/`r"..."` and malformed `"""abc` openings classify as `COMPLETE`).
  - `org.babblelang.Repl` is the loop on top: prompts, multi-line input, `:help`/`:type`/`:load`/`:cancel`/`:quit`, values shown (strings quoted), errors printed without ending the loop. `:type` is `BabbleSession.typeOf` (analysis without commit or run; `ScopeAnalysis.resultType()`, set by `TypeChecker.run` from the last statement and rendered as source syntax by `TypeDisplay`, which diagnostics don't use); `:load` is `BabbleSession.eval(source, path)`.
  - Lines come from an `org.babblelang.repl.LineSource` (BIP004 §9): `PlainInput` (pipes, tests) or `TerminalInput` (JLine, front end only: never in the runtime jar). `BabbleLineParser` makes Enter accept only inputs `classify` doesn't find incomplete, so multi-line inputs are edited and recalled whole; `Completions` (JLine-free, tested in `TerminalInputTestCase`) offers commands, names, keywords, `:load` paths and members after a chain of plain names, by lookups only, never calls. `Main.isTerminal()` uses `Console.isTerminal()` reflectively, since JDK 22+ returns a console for piped input. `org.babblelang.Main` is the command line: it runs a script as the first input of a session (`BabbleSession.eval(source, sourceName)`), binds `args` (`JavaObject.of(list)`), and starts the loop when there is no script or with `-keep-alive`.
  - Parsing is shared with `compile()` (`BabbleScriptEngine.parse`), which reports `Syntax error : unexpected …` with line and column; type diagnostics throw `TypeCheckException`.
- **Analysis** (`org.babblelang.analysis`): runs in both modes at `compile()` time, in four passes, in this order (`BlockScopes.analyze`):
  1. `BlockScopes` computes each scope's `def`s for hoisting, standalone `effectDeclaration`s, and the members of classes, objects and interfaces (`TypeNode`), and checks placement (`return`, `this`, `super`, `private`, header `def`s, value-class rules).
  2. `TypeChecks` resolves `implements`/`extends` statically (interface literals or Java interfaces), checks completeness, default conflicts, Java arities and `super`, and reports private/read-only access when the receiver's class is statically known.
  3. `Resolver` (result: `ScopeAnalysis.resolution()`) binds every name to a frame `Variable` or to a runtime lookup; only the compiler uses it.
  4. `TypeChecker` + `EffectChecker` (`docs/design/bip003_type-system.md`, `docs/design/bip008_static-typing.md`, `docs/design/bip007_effects.md`, `docs/design/bip010_type-checker-simplification.md`, `docs/design/bip027_tackling-complexity-in-the-compiler.md`) run static typing over `Type` (`any`, `byte`..`string`, `null`, nullable `T?`, union `A | B`, `TypeVar`, effect-annotated function types `Type.Function` with `EffectSet` and `mut`/`borrow` parameters, intersections of interfaces `A & B` (`Type.Intersection`, `BIP022`), arrays `array of T` (`Type.Array`, `BIP020`), nominal/parameterized class/interface instance types with `of` syntax, class values, modules, Java packages, Java classes and interfaces) using package-private collaborators (`BIP010` §7, `BIP027-I1`/`I3`–`I4`): `TypeAlgebra`, `TypeAnnotations`, `MemberTypes` (including iterable resolution), `OperatorTypes`, `CallSolver` + `OverloadCallResolver` + `CollectionCallChecker` + `JavaCallSolver`, `JavaTypeBridge` (sharing `Overloads.isMoreSpecific` with the runtime), `Narrowing` + `TypeEnv`, `SlotInference`, `TypedProgram`, `LoweringAnalyzer`, `StaticRefs`, `SyntaxText`, and `TypedModuleSummary`/`ImportedSummaries`. `EffectChecker` is split into `EffectModifiers`, `AlgebraicVerifier`, `EffectBodyWalker`, `CallEffectAnalyzer`, plus ANTLR-free cores `Reachability` (depth-bounded `k = 3` `PathKey` widening and `BIP027-D5` prefix-overlap `mut` exclusivity), `JavaEffectResolver` (all `java.lang.reflect.*` and scoped redundant-axiom tracking), `EffectFixpointDriver` (Bourdoncle WTO), and `SymbolicEffectSummary` (single-pass $O(k)$ intra-file and cross-module HOF instantiation with `BIP019` `readParams` forwarding). `TypeChecker.run` converges the slots, infers effects, re-converges once, then makes a single verification walk; expressions go through an explicit `typeOf(ctx, expected, role)` dispatch, and every `int`→`double` conversion is recorded by `coerce`. Features include generic call/constructor inference and covariance, call-site parameter inference (`BIP008-I7`) for non-exported/non-escaping/non-interface callables, inference for unannotated defs and members across their assignments via Tarjan lexical SCCs + monotone `SlotCell` worklist convergence, flow-sensitive narrowing (`is`, `else` subtraction, `== null`/`!= null`/`<> null`/truthiness, `while` loops), safe navigation `?.`, Bourdoncle WTO effect/algebraic inference & verification (`RM002` / `BIP007-I1`, `BIP016`, `BIP017`, `BIP019`, `BIP027-I3`–`I4`), and diagnostics (`ScopeAnalysis.typeDiagnostics()`) worded like the runtime errors they predict.
  - Runtime checks (`BIP008-I5`–`I6b`): `TypeChecker` records `ScopeAnalysis.widensToDouble(ctx)` wherever `int` widens to `double` or `double?` (parameters, returns, `def`s, assignments, `if`/`while` joins) and records `ScopeAnalysis.checkedType(ctx)` for `as` casts and for Java generic calls/field reads whose reflection type is a `TypeVariable`/`WildcardType` resolving to a non-`any?` type (supporting `union`, `null`, `any`, and non-nullable `Builtin`/`FunctionType`/`JavaClassType`/`NominalType` with an id per class/interface expression: in a module, its key and the type's name, `lib/vec3.ba#Vec3`, stable across compilations; elsewhere JVM-unique, `T17`). `ClassShape` retains declared member and static types for `InterpretedInstance`/`BabbleObjects`/`BabbleType.setMember` (used by external Java writes and `any` writes), while Babble-side `this.x = …` direct field writes in `HirEmitter` omit checks. `JavaTypes.checkBoxed` (in `JavaMethod`, `JavaLinker`, `JavaClass`, `JavaDefaultCall`) rejects `null` for boxed primitive returns/fields (`Integer`, `Double`, `Boolean`), and `JavaTypes.checkParameters` (in `Faces`) checks arguments entering Babble from Java interfaces.
  - Results live in `ScopeAnalysis` via public sub-views (`lowering()`, `calls()`, `hierarchy()`, `effects()`; `BIP027-D3`) alongside top-level ANTLR-free `PrimitiveKind` and `LoweringTargets` (so `ir`/`opt`/`compiler` never import `ScopeAnalysis`, enforced by `ArchitectureBoundaryTestCase`). Non-typecheck warnings go to the context's error writer as `Warning : ...`, type diagnostics as `Error : ...`; errors become `ScriptException`s worded like runtime ones.
- **Modules** (`docs/design/bip005_modules.md`): `export def x = …` (top level of a file only, checked by `BlockScopes`; names in `ScopeAnalysis.exports()`) and `import("path.ba")`.
  - Loading: `ImportFunction` sends names ending in `.ba` to `BabbleScriptEngine.importModule`, which goes through the runtime's `Modules` to the engine's `EvalModules.load`. The engine's `ModuleSource` (*M4*, `docs/design/bip006_module-sources-and-aot.md` §4; the `babble.moduleSource` attribute, default `FileModuleSource.INSTANCE`; also `FileModuleSource.rooted(dir)`, `MapModuleSource`, `ClassPathModuleSource`, sharing `LogicalPaths` for `/`-separated paths) resolves the name from the importing module (a `ModuleId`: key + display name; the importer's source name maps back to it through `compiledAs`, else `ModuleSource.identify`, which for files accepts a `FILENAME` that does not exist).
  - Running: the module is compiled in the engine's mode and run once per eval on a `ScriptRuntime` of its own (own root namespace, same context and bindings, the eval's loaded modules keyed by `ModuleId.key`). The result is a `runtime.Module`: a read-only `HasMembers` view (plus `exportAt(int)` indexed access for `RM001`) of the exported names of that root, registered before the file runs so that cycles work. No backend has module-specific code: both script classes extend `BabbleScript` (`eval(ScriptRuntime)`, `exports()`).
  - *Static imports* (M2): pass 1 records each `import("….ba")` call with a string literal (`BlockScopes.imports`); after pass 1, `BlockScopes.analyze(…, ModuleLoader)` hands the file's `ModuleInterface` (exported names) to the loader (`started`, for cycles), then loads each import's interface (`load`; the engine's `Loader`, relative to the importing file), and `TypeChecks` resolves `implements`/`extends`/`super(I)` paths through modules (`resolveDefinition`, `moduleOf`, the exporter's `resolveExport`) and reports `No such export` / `Cannot assign to an export` (errors).
  - The module cache (`compiledModule`, under `moduleLock`) keys by `ModuleId.key` and keeps a module's compiled script and interface while the source, the mode and the version (`ModuleSource.version`; a content hash for files) of every module its analysis read are unchanged; runtime `import` goes through it too.
  - *Types across modules* (M3): a static import's type is `Type.Module`, whose members are the exporter's types; the `ModuleInterface` carries the exporter's AST-detached `TypedModuleSummary` once it ran (`typed`, read with `summary()`; `BlockScopes` keeps it as `pass.summary`, never the `TypeChecker`), so importers query lock-free exported types, declarations, members, and `CallableEffectTemplate`s without retaining the exporter's `TypeChecker`. Annotations naming a class through a module (`shapes.Circle`, or an alias of it) are nominal `Instance` types (`typeThroughModule`). Reading an export of a file still being analysed in an import cycle reports `Missing type : <name> (import cycle with <module>)`.
- **Block scope**: the file, function literals (parameters + body top level), and every other block (block expression, `if` branch, `while` body — fresh per iteration) are scopes. Names a scope defines are declared (unset) on entry; reading or assigning them before their `def` runs fails with `Name used before definition`. Blocks that define nothing get no namespace. Top-level `def`s of class, object, interface and static bodies declare *members*, which bind no unqualified name (reading an uninitialized body member fails with `Member used before definition`).
- **Object model** (`docs/design/bip002_object-model.md`): `class (params) implements I ( body ) static ( … )`, `record`, `interface extends … ( … )`, `object implements … ( … )`, `this`, `super.m()`/`super(I).m()`, `x is T`, `private`, and the natives `same`/`classof`. Members are reached only as `this.x` or `obj.x`; `this.x` goes through `Members.selectOwn`/`assignOwn`, the only path that may see private members.
  - *Operator methods*: when the left operand of `+ - * /`, or the operand of unary `-`, is a Babble object (`BabbleObjects.isBabbleObject`), the operator calls its public `plus`/`minus`/`times`/`div`/`neg` (`Operators.method`, `Operators.NEGATE`; missing: `No such member : plus`). The interpreter does it in `visitBinaryOp`/`visitNegate` (`operatorCall`); compiled code evaluates both operands into locals, then branches on `BabbleObjects.isBabbleObject` to the same select and call `invokedynamic` sites `a.plus(b)` compiles to (`operatorCall`) when non-numeric, or lowers directly to JVM primitive instructions when statically numeric (`RM001`). Both use `SyntaxText.operatorSite` for the call's messages. The type checker types it as that call when the left type is an `Instance`.
  - *Compound assignment* (`x op= v`, the `op` token of `# assignExpression`, `Operators.compound`) is `x = x op v` with the target read before `v` and an `obj.x` receiver evaluated once: the interpreter's `compound`, the compiler's `AssignAndMemberEmitter` (sharing `ControlAndOpEmitter` arithmetic), and the type checker's `compoundAssignment` (sharing `binaryOp`); the left operand's text in messages is `SyntaxText.targetText` (`x`, `obj.x`).
  - Runtime: `BabbleClass` (callable class value, statics, inherited defaults, `capturedFor` interface cells), `InterpretedInstance` (interpreter-only member array, `face()` `Proxy` cache, record equality/hash/`toString`), `BabbleObjects` (`ClassValue`-cached `$babble$*` metadata across plain compiled classes and `InterpretedInstance`s), `ArraySupport` (runtime array creation, `size`/`get`/`set`, content equality/hash/printing, and interpreter side table of Babble element classes, `BIP020`), `BabbleInterface`, `ClassShape` (static description, string-encoded for compiled code), `Classes` (helpers both backends call), `Supers`. Java boundary: `Values.toJava`/`fromJava`/`unwrap`, `Faces` (`Proxy` faces for interpreted instances implementing Java interfaces, and cached `LambdaMetafactory` factories for `0..16`-arg accessible functional interfaces with `Proxy` fallback for inaccessible/higher-arity SAMs), `Overloads`/`JavaTypes`.
- **Runtime boundary** (`docs/design/bip006_module-sources-and-aot.md` §3): what a compiled program needs to run is `org.babblelang.runtime` and the built-ins of `engine.impl.natives` and `engine.impl.natives.java`.
  - `BabbleException` is in `runtime` too, so error messages start with `org.babblelang.runtime.BabbleException:`. The boundary references nothing of the front end (parser, analysis, ir, opt, compiler, interpreter, engine), no third-party library and no JDK module but `java.base`; `RuntimeBoundaryTestCase` enforces it by reading the class files' constant pools. `mvn package` also builds it alone as `babble-<version>-runtime.jar` (classifier `runtime`).
  - `import` reaches modules through the runtime interface `Modules` (`load(name, importerSourceName, rt)`), which the engine implements; `ScriptRuntime` is `(root, writer, modules)`, with no `javax.script`.
  - *babblec* (M5b): `compiler.Babblec.compile(main, root, jar, context[, optLevel])` compiles through `BabbleScriptEngine.compileProgram(source, mainName)` (a `FileModuleSource.rooted(root)`, compile mode, with `BIP014-D2` AOT cross-module small-export inlining enabled at `-O1`+; the main module and every module its analysis read, as `ProgramModule`s) and writes a reproducible jar (sorted entries, fixed time stamps): the generated classes, the index `babble/modules.index` (`runtime.ProgramIndex`: main key, the root relative to the jar's directory; per module key, display name, class, exports), the runtime classes copied from wherever `Launcher` was loaded, and `Main-Class: org.babblelang.runtime.Launcher`.
  - The launcher runs the main class's `run(ScriptRuntime, Namespace)` with `args` bound and a `Modules` over the index, resolving import names from the importer's key with `runtime.LogicalPaths`; a module not in the index goes to a `runtime.ModuleCompiler` found through `ServiceLoader` (M5c: the full jar registers `compiler.FileModuleCompiler` in `src/main/resources/META-INF/services`, an engine per root compiling through `compileProgram`; the program's own modules stay the jar's at runtime), and without one fails with `a compiled program only has the modules it imports statically`.
- **Runtime** (`org.babblelang.runtime`, no ANTLR dependency): everything both backends call — `Operators`, `Truth`, `Members`, `Arguments` (the one implementation of argument binding), `Calls`, the `Callable` calling convention `call(ScriptRuntime, Object[] args, String[] names, CallSite)`, `BabbleFunction`/`BoundMethod`, `CompiledFunction`/`FunctionBody`, `IntCell`/`DoubleCell`/`BoolCell`, `CallSite`/`OpSite` (source texts for error messages), `ScriptRuntime` (per-eval root namespace, output writer, `Modules`), and the scopes `Namespace`/`Scope`/`Slot`.
- **Interpreter** (`org.babblelang.engine.impl.Interpreter`): extends the generated `BabbleBaseVisitor<Object>`; one `visitX` method per grammar alternative. It tracks the `last` visited context so `BabbleCompiledScript` can report the line number on error. `return` is a `ReturnException` caught by `Function.invoke`. A self tail call (`BIP024`, marked by `analysis.TailCalls`, `ScopeAnalysis.isSelfTailCall`) returns a `TailCall` that `Function.invoke` runs as its next activation; the compiler lowers it to `HirExpr.SelfTailCall`, a jump back to the start of the method in `HirEmitter`, at every optimization level. `forever e` (`BIP024-D9`) is `e` in both backends. Class constructors are `InterpretedClassBody`.
- **IR, Optimizer & Compiler** (`org.babblelang.ir.hir`, `org.babblelang.ir.egraph`, `org.babblelang.opt`, `org.babblelang.compiler`, `docs/design/bip001_bytecode-compiler.md`, `docs/design/bip014_optimization-passes.md`, `docs/design/bip027_tackling-complexity-in-the-compiler.md`): `BabbleCompiler` lowers the analysed parse tree via `HirBuilder` (the sole ANTLR4 bridge) into an ANTLR-free `HirModule` (51-variant sealed `HirExpr`, `HirFunction`, `HirClass`, `HirInterface`, `ExprMeta`), runs `PassManager.defaultFor(optLevel)` (`-O1` default: bounded fixed-point over `HirEGraphSimplifyPass` backed by the zero-dependency `org.babblelang.ir.egraph` `EGraph` + `AlgebraicRules`, `InlinePass`, `HirDcePass`, and `HirLicmPass`, sharing `HirRewriter.rewriteModule` and verified by `HirVerifier` when `babble.verify=true`), and hands the optimized `HirModule` to `HirEmitter` (coordinating `MethodEmitContext`, `JvmPrimitives`, `BridgeHelpers`, `AssignAndMemberEmitter`, `ControlAndOpEmitter`, `CallEmitter`) + `ClassGen` + `InterfaceGen` + `ConstantPool` + `ScriptClassWriter` to emit a script class (a module's is named after its key, `BabbleCompiler.className`: `lib/vec3.ba` → `babble/lib/vec3$ba`, the same every compilation; other scripts get `org/babblelang/generated/Script$N`). `ArchitectureBoundaryTestCase` enforces import boundaries (zero `engine.impl` reverse-refs, ANTLR and `ScopeAnalysis` isolation, reflection isolation in `EffectChecker`) and ≤ 2,000-LOC ceilings on refactored compiler classes (`CallSolver`, `HirEmitter`, `EffectChecker`).
  - Its methods: `run(ScriptRuntime, Namespace)` (split into `run$k` when large); per function literal, a direct entry point `fn$N$name` (`(self, thiz, rt, binder, Object p0, …)`), an optional `$spec` primitive-signature entry point (`fn$N$name$spec`) when any parameter or return is unboxed (`byte`..`char`), plus an `fn$N$name$call` array adapter (wrapped as `FunctionBody` via `LambdaMetafactory`; functions with more than 200 parameters only have the array form); one `cls$N$Name` constructor per class/object expression (wrapped as `ClassBody`); real JVM `interface` classes (`InterfaceGen`, `Script$N$iface$k$Name` / `babble/<module>$iface$k$Name`) with `bm$<name>` / `bm$<name>$spec` and JVM `default` methods (`RM003`); and static constant fields built in `<clinit>` helpers.
  - Phase 2, `RM003` & `BIP020-I1`: function, block, class-body and static-block variables are JVM locals, or `Cell`s / `IntCell`..`CharCell` when captured (function, class, and interface values carry their captured cells); the file and interface bodies keep phase 1 namespaces. Each class/record/object expression gets its own plain JVM class `Script$N$k$Name extends java.lang.Object` (`BIP020-D18`: no runtime base class; `$babble$classStatic`, `$babble$class`, `$babble$rt`, per-class `equals`/`hashCode`/`toString`, and `$babble$javaDefaultLookup()` generated directly) implementing its Babble JVM interfaces (`bm$<name>` / `bm$<name>$spec` bridges + `$iface$<Id>`) and accessible Java interfaces (exact-signature Java overload bridges without `Proxy` allocation), with a field per member — unboxed primitives for non-nullable primitive members, with an `int $defined` bitmask and `$babble$isDefined` when any unboxed body `def` may be read before init — methods as instance methods + optional `$spec` behind shared `CompiledMethod`s, and hidden `$v$x` fields for constructor cells methods capture; `this.x`/`this.m()` compile to `GETFIELD`/`PUTFIELD`/`INVOKEVIRTUAL` (of `$spec` when typed and positional, else direct entry point).
  - Phase 3, `RM001`, `RM003` & `BIP020`: other calls and `obj.x` selections are `invokedynamic` sites bootstrapped by `runtime.Bootstrap` (including typed primitive call sites `(Callable, ScriptRuntime, CallSite, <prim...>)<prim>` resolving to `spec` handles, and `SelectCache` inspecting primitive/reference fields via `MethodHandles.privateLookupIn` across class loaders), with an inline cache of up to 4 guarded fast paths before going generic. Where `TypeChecker` resolves a target statically, `RM001`/`RM003`/`BIP020` emit direct Babble `INVOKEINTERFACE` (`bm$<name>$spec`/`bm$<name>`), `INSTANCEOF`/`CHECKCAST` for `is`/`as`, `INVOKESPECIAL` for `super(I).m()` (with `$super$k` lambda-hoisting helpers), array `NEWARRAY`/`ANEWARRAY`/`ARRAYLENGTH`/`<X>ALOAD`/`<X>ASTORE`, Java `INVOKEVIRTUAL`/`INVOKESTATIC`/`INVOKEINTERFACE`, `NEW`, field `GET*`/`PUT*` (with `Values.unwrap`, `JavaTypes.checkBoxed`/`wrapInvocationException`, and `Types.check` parity), and indexed `Module.exportAt(index)` reads without `invokedynamic` or `JavaLinker` overhead. Java overload resolution is cached per argument kinds (`Overloads.Cache`, both modes), and its candidates (`JavaTypes.methods`) skip bridge methods except visibility bridges (`StringBuilder.length()`).
  - Invariants: non-`RM001` expressions leave `Object` (`RM001`/`RM005` leave unboxed JVM primitives and adapt at boundaries via `emitAs`), and the operand stack is empty at loop heads (HotSpot OSR). `return` emits `IRETURN`/`DRETURN`/`ARETURN` matching the enclosing method/spec descriptor; classes load lazily through per-compile `ScriptClassLoader`s chained across static module imports (`CompositeClassLoader`) and REPL session inputs, with an in-memory hierarchy table backing `ClassWriter.getCommonSuperClass`. Error lines come from the innermost stack frame of the script's classes with a line number (preserved on inlined and LICM-hoisted nodes per `BIP014-D5`).
- **Scoping** (`runtime` package): `Scope<T>` interface with `Slot` holders (`set` initialises, `assign` requires the slot to be set); `Namespace` is the main implementation (`child`, `declare`, `initialize`, `assign`, `lookup`). Objects are not namespaces (plain compiled classes or `InterpretedInstance`s).
- **Natives**: built-ins implement `runtime.Callable`.
  - Native functions live in `impl.natives`: `print` writes to the `ScriptContext` writer, or `to:` any `Appendable`; `same`; `classof`; `ConvertFunction`, `int(x)` truncating towards zero and failing out of range, `double(x)`, both parsing strings, typed `int`/`double` by `TypeChecker.implicitType`; `CoreCollections` (`array`, `list`..`entry`).
  - Java interop lives in `impl.natives.java`: `JavaPackage` → `JavaClass` (a `JavaType`, equal by `Class`; members are public member classes, methods, then public fields: static final ones cached as constants, others read on each selection and never cached by `Bootstrap`, `isConstant`; instance fields only through an instance, `value(receiver, name)`; `assign` writes a public non-final field, `Members.assign` sending Java targets there, and refuses a Babble function for a functional-interface field, which needs `Runnable(f)` since member assignment has no `ScriptRuntime`) → `JavaMethod`/`BoundJavaMethod`/`JavaObject` (a `JavaValue` wrapper for objects Babble constructs, printing as its value; `JavaMethod` checks `JavaTypes.checkBoxed` outside its invocation `try/catch` so `BabbleException` errors are not double-wrapped).
  - Java calls return objects unwrapped; `Members.select` gives any Java object other than Babble's own values (null, boxed primitives, `String`, callables) its members through `JavaObject.member` (and arrays `size`/`get`/`set`/`equals`/`hashCode`/`toString` via `ArraySupport`), and `Overloads.resolveMethod` calls a method of an inaccessible class (`List.of()`'s) through the accessible type it comes from (`JavaTypes.accessible`). The type checker types a Java result or static field as `JavaInstance` of its accessible class (`any` for `Object` or when no accessible type exists), and arrays as `Type.Array` (`array of T`). Calling a functional interface's class with one Babble function converts it explicitly.
- **Formatter** (`org.babblelang.format.Formatter`, command line `-format`, `org.babblelang.Babblefmt`): works on the token stream, comments included (the lexer puts them on the hidden channel, so the parser never sees them; anything counting tokens must look at the channel, as `BabbleSession.classify` does).
  - It reads in the parse tree (`BabbleScriptEngine.parseSource`) what each token is: a call's `(` or a block's, a newline that separates expressions (`sep`), continues one (+1 indent), sits in a parenthesised list, or precedes a block/`else`/`static` (dropped unless a comment is in the way). It keeps the source's line breaks otherwise; indentation comes from a stack of open parentheses, each anchored to the line where its `if`/function/class starts. Multiline `"""..."""` and `r"""..."""` blocks canonicalize `minIndent` to `(line.indent + 1) * 4` spaces (preserving `oldMinIndent` when a participating line has an intentional extra leading tab), strip trailing horizontal whitespace, and emit blank lines as `""`.
  - The result is parsed again and must give the same tree, newlines and semicolons aside (`shape()` normalizes multiline string tokens by `StringLiterals.decode` so canonical re-indentation passes while content drift fails with `IllegalStateException`). Note that `;;( … ;;)` closed on its line and followed by code lexes as a line comment (longest match).
