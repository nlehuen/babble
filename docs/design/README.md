# Babble Improvement Proposals (BIPs)

Design documents and language proposals for Babble, numbered chronologically by creation date in the git history.

## Naming convention

Items within each proposal use stable identifiers prefixed by the BIP number:

- **`BIP###-Q#`** — open questions (e.g., `BIP007-Q1`). Resolving a question gives a corresponding decision (`BIP###-D#`).
- **`BIP###-D#`** — decision points (e.g., `BIP001-D1`, `BIP002-D3`). Where a decision settles an earlier question, both are linked (e.g., `BIP005-Q1` → `BIP005-D1`, or `BIP001-Q1` → `BIP003-D1`).
- **`BIP###-P#`** — implementation phases (e.g., `BIP001-P0`–`BIP001-P4`, `BIP008-P1`–`BIP008-P7`; sub-phases may carry a letter suffix such as `BIP001-P0a` or `BIP008-P6a`).

Roadmap stages group related work across proposals into sequential milestones:

- **`RM###`** — transversal roadmap stages (e.g., `RM001`, `RM002`). Each `RM` stage bundles multiple BIP items across several topics into a cohesive delivery slice.
  - **Referencing rule:** Outside `docs/design/README.md`, only **past (already implemented)** `RM###` milestones may be mentioned, with the sole exception of a PR or commit description that is directly implementing that `RM###` (e.g., mentioning `RM999` in the PR or commit description implementing `RM999` is fine). Unimplemented `RM###` identifiers must never appear anywhere else — not in code or tests, not in other docs or BIPs (refer to stable `BIP###` / `BIP###-P#` / `BIP###-D#` identifiers instead), and not in unrelated commit or PR descriptions — so the future part of the roadmap can be modified, merged, split, or reordered at will.

## Cross-BIP baseline

With `BIP001-P0`–`BIP001-P3`, `BIP002-P1`–`BIP002-P6`, `BIP004`, `BIP005-P1`–`BIP005-P5`, `BIP006-P1`–`BIP006-P6`, `BIP008-P1`–`BIP008-P7`, `RM001`, `RM002` (`BIP007-P1`), `BIP009-P1`–`BIP009-P4`, `RM003`, and `RM004` (`BIP010-P1`–`P6`) landed, Babble has:

- A shared, `java.base`-only runtime (`BIP001-P0`, `BIP006-P1`) and dual-mode execution (parse-tree `Interpreter` + ASM `CodeGenerator` with `invokedynamic` call/select/Java inline caches).
- Classes, value classes, objects, interfaces with default methods, and two-way Java interop (`BIP002`, lowered in `RM003` to native JVM interfaces, direct Java-interface bridges in compiled mode, and cached `LambdaMetafactory` SAM adapters).
- Nested interactive sessions (`BIP004`), cross-file modules with `ModuleSource` abstractions (`BIP005`, `BIP006-P2`–`P3`), and reproducible AOT jars (`babblec` `-compile`, `BIP006-P4`–`P6`).
- Mandatory static typing (`BIP008`) with `any`/`any?`, `T?`, `A | B`, `?.`, `as`, flow-sensitive narrowing, generics (`(...)`), call-site parameter inference, and `int`→`double` conversion on numeric joins (`BIP008-D7`), eliminating internal `BIP003-D9` runtime checks.
- Typed primitive lowering & static dispatch (`RM001`): unboxed `int`/`double`/`bool` locals, closure cells (`IntCell`/`DoubleCell`/`BoolCell`), compiled class fields, `$spec` entry points, typed `invokedynamic` calls, direct static Java dispatch, indexed module exports, and cross-classloader primitive field inline caches.
- Core static effect & `axiom` contract layer (`RM002` / `BIP007-P1`): SCC fixed-point inference and verification for `{pure, hermetic, mut, borrow, deterministic, nothrow}`, compositional algebraic properties (`idempotent`, `commutative`, `associative`, `monotone`, `injective`), `@PARAM`/`@THIS` alias tracking and static call-site `mut` exclusivity, frame-local `borrow` closures, bounded call-site higher-order specialization, cross-module `ModuleInterface` & REPL `AnalysisSession` persistence (`BIP007-D2`), and the 7-tier Java host contract layer (`axiom`/`impure`, `org.babblelang.effects`, `BabbleScriptEngine`).
- Systematic differential & coverage harness (`BIP009`): `.batest` multi-module/multi-session specification runner (`61` `.batest` files / `869` cases) with leak-free error normalization and dual-JVM `-Pbatest` JaCoCo coverage reporting across `Interpreter`, `Compiler`, `Shared Front-End`, and `Shared Runtime` (`>= 75%` branch coverage gate).
- JVM interfaces & proxy-free adapters (`RM003`): Babble interfaces compiled to real JVM interfaces (`INVOKEINTERFACE`, `INSTANCEOF`, `INVOKESPECIAL` `super(I).m()`, cross-module/session `ScriptClassLoader` hierarchy), direct Java-interface `implements` clauses and exact-signature overload bridges on compiled Babble classes (retiring `Proxy` faces in compiled mode), and cached `LambdaMetafactory` SAM callback adapters for `0..16`-arg accessible functional interfaces (with `Proxy` fallback only for inaccessible, child-loader, or `>16`-arg SAMs).
- A modular front end (`RM004` / `BIP010`): the 6,828-line `TypeChecker.java` decomposed with zero semantic change into package-private collaborators (`TypeAlgebra`, `CallSolver`, `JavaTypeBridge`, `TypeAnnotations`, `MemberTypes`, `OperatorTypes`, `Narrowing`, `SlotInference`, `LoweringAnalyzer`, `TypedProgram`, `TypedModuleSummary`, `ImportedSummaries`, `StaticRefs`), one `SlotCell` inference engine with a single verification walk, and no retained `TypeChecker` across modules or session inputs.

The next immediate milestone is **Babble core types & Java nullability alignment (`RM005`, `BIP011-P1`–`P6`)** (all 9 scalars `byte`..`string` with 8-primitive unboxing, 5 core `java.util` collections `list`..`sortedmap` + `entry`, universal `C(T)(...)`, mutable generic invariance + `borrow` covariance, `@NotNull`/JSpecify + `java.base` parametric nullness + `e!` + defensive boundary checks, and built-in `BIP007` effects). Building on `RM004` and `RM005`, the remaining roadmap covers **ownership lattice, bytecode optimization & axiom verification (`RM006`, `BIP007-P2`–`P3`)**, **language, import & indexing ergonomics + structural types (`RM007`)**, **stdlib, interactive mode & build tooling (`RM008`, plus deferred GraalVM native-image metadata from `BIP006` §9)**, and **verified parallelism (`RM009`)**.

### RM001 — Typed Primitive Lowering & Static Dispatch *(Implemented)*

Exploits `BIP008`'s non-`dynamic` static types across analysis publication, primitive codegen, Java interop dispatch, and module/session field specialization so `CodeGenerator` eliminates redundant boxing, reflection, and dynamic call fallbacks. See [bip001_bytecode-compiler.md §19](bip001_bytecode-compiler.md#19-design--implementation-notes-rm001--typed-primitive-lowering-and-static-dispatch) for design notes and benchmark results.

- **Spans:** [BIP001](bip001_bytecode-compiler.md) (§10.5, §19), [BIP002](bip002_object-model.md) (§4.11), [BIP003](bip003_type-system.md) (§6), [BIP004](bip004_repl.md) (§8), [BIP005](bip005_modules.md) (§8.3), [BIP008](bip008_static-typing.md) (§7.1)
- **Depends on:** `BIP008-P4`–`P7`
- **Landed across topics:**
  - *Analysis publication (`BIP003` §6, `BIP008` §7.1):* `TypeChecker` publishes converged `PrimitiveKind`, definite-initialization flags, and static Babble/Java/Module targets into `ScopeAnalysis` (and freezes types in `AnalysisSession`), superseding a standalone AST `Unboxing` pass.
  - *Primitive codegen (`BIP001` §10.5/§19, `BIP002` §4.11):* Unboxed non-nullable `int`, `double`, and `bool` locals, closure cells (`IntCell`/`DoubleCell`/`BoolCell`), and class fields (`$defined` bitmask for primitive body `def`s); primitive JVM arithmetic and comparisons (`Double.compare` for NaN/signed-zero parity); `$spec` entry points (`fn$N$name$spec`, `m$name$spec`) alongside `$direct` and `$call`; typed `Bootstrap.call` sites; type-guarded `int` constant folding; boxed `classof(1)`/`classof(1.5)`/`classof(true)` parity (`BIP002` §4.11).
  - *Static Java dispatch (`BIP001` §10.5):* Direct `INVOKEVIRTUAL`/`INVOKESTATIC`/`INVOKEINTERFACE`/`NEW`/`ARRAYLENGTH`/field `GET*`/`PUT*` with `Values.unwrap`, `JavaTypes.checkBoxed`/`wrapInvocationException`, and `Types.check` generic boundary parity.
  - *Static imports & session fields (`BIP005` §8.3, `BIP004` §8):* Indexed `Module.exportAt(index)` reads for non-cyclic static imports, and cross-classloader primitive field getters in `Bootstrap.SelectCache` (`MethodHandles.privateLookupIn`).
- **Verification:** Dual-mode `mvn -B package` (`interpret` + `compile`/`CheckClassAdapter`, including `RuntimeBoundaryTestCase`), bytecode/unit/differential/REPL tests, `-format -check`, byte-identical `examples/raytracer-argon/scene.ppm` (`59.3 s` → `46.1 s`), `raytracer-fable` (`72.9 s` → `67.9 s` wall / `65.9 s` render), and `Benchmarks` (`while loop` `0.1 ms` / `769.4x` vs interpret, `fib(25)` `1.7 ms` / `71.4x`, `ArrayList` `2.0 ms` / `13.3x`).


### RM002 — Core Effect & `axiom` Contract Layer *(Implemented)*

Lands the complete static effect & algebraic-property front end (`BIP007-P1`, `BIP007-D1`–`D4`) across grammar, formatting, `TypeChecker`/`EffectChecker`, `value class` & interface conformance, cross-module export, interactive sessions, and host Java boundaries—100% front-end with zero `babble-runtime`, `Interpreter`, or `CodeGenerator` changes.

- **Spans:** [BIP007](bip007_effects.md) (§9.1, §9.2 `BIP007-P1`), [BIP002](bip002_object-model.md) (§4.6, §6.2), [BIP004](bip004_repl.md) (`AnalysisSession`), [BIP005](bip005_modules.md) (`ModuleInterface`), [BIP006](bip006_module-sources-and-aot.md) (`babble-runtime` boundary), [BIP008](bip008_static-typing.md) (`Narrowing`, call-site inference)
- **Depends on:** `BIP008-P1`–`P7` *(100% front-end; `unique`/`move`/`freeze`/`frozen`, `@TERMINATING`, bytecode optimizer passes, and unused `pure nothrow` compile errors are deferred to `RM006`)*
- **Decisions resolved (`BIP007-D1`–`D4`):**
  - `BIP007-D1` (`Q1`): Flow-sensitive `Narrowing` (`!= null`, `is T`) establishes `nothrow` on guarded branches and short-circuit `and`/`or` right-hand sides; `RM006` optimizers never reorder narrowed predicates ahead of their guards.
  - `BIP007-D2` (`Q2`): Unannotated `export def` exports its inferred `EffectSet` and parameter flags via `ModuleInterface`; exports with explicit effect modifiers or `impure` expose only their declared contract.
  - `BIP007-D3` (`Q3`): `associative` takes no `identity(...)` clause in `RM002` (combiners take explicit seeds as in `BIP007` §8.4).
  - `BIP007-D4` (`Q4`): `axiom` stays strictly at declaration/function granularity (`def f = axiom ... ->`, `axiom ... Target`, `def C = axiom ... import("...")`, `export axiom ...`); inline `axiom (...)` expression blocks are forbidden.
- **Landed across topics:**
  - *Syntax & formatting (`BIP007` §4.1):* Contextual `ID` predicates in `Babble.g4` (`axiom`, `pure`, `hermetic`, `mut`, `borrow`, `deterministic`, `nothrow`, `idempotent`, `commutative`, `associative`, `monotone`, `injective`, `impure`) on function literals, parameter declarations, function types, and declaration-level `axiom`/`impure` rules (`Class()` constructor-only targets vs bare `Class`), plus canonical `Formatter` rules (`(mut x: T): R -> ...` and `Class()`). (`unique`, `move`, `freeze`, and `frozen` syntax await `RM006`.)
  - *Effect & algebraic checker (`BIP007-P1`, `BIP008`, `BIP002`):* `EffectSet`, `HostEffects`, `EffectChecker`, and `Type.Parameter(..., mut, borrow)`; Tarjan SCC bottom-up fixed-point inference and verification for `{pure, hermetic, mut, borrow, deterministic, nothrow}` integrated with `BIP008` call-site inference, generics, and `Narrowing`; `mut` inferred on `this` and parameters **only** on completely untyped functions (existing `.ba` scripts/examples migrated where typed functions mutate `this`/parameters); `@PARAM`/`@THIS` local alias and derived sub-reference tracking (local `def` reassignments stay valid in `pure`, while mutating fresh local objects in `pure`/`hermetic` awaits `unique` in `RM006`); static call-site `mut` exclusivity (same bindings, tracked aliases, identical member paths); compositional algebraic properties and signature checks; frame-local `borrow` closures attributing unescaped local `def`s; bounded call-site effect specialization for statically resolved concrete Babble callables; `value class` constructor & standard protocol (`equals`/`hashCode`/`toString`/`compareTo`) defaults + immutable non-`mut` `string` receivers; effect-aware `Type.Function` subtyping and interface override conformance (`actual <: required`).
  - *Module, session & Java boundaries (`BIP005`, `BIP004`, `BIP006`, `BIP007` §6):* Order-independent file/`package` `axiom` and `impure` declarations (`Class()` constructor-only targets vs bare `Class` for all public constructors and methods); exported `axiom` and effect tables in `ModuleInterface`; session persistence in `AnalysisSession`; public `org.babblelang.effects` package (`Effect` enum and `@Pure`..`@Impure`) and per-engine `BabbleScriptEngine` registries (`allowAxioms`, `assumeEffects`, `assumeConstructorEffects`, `markImpure`).
- **Verification:** Dual-mode `mvn -B package` (`interpret` + `compile`/`CheckClassAdapter`), `RuntimeBoundaryTestCase` (zero runtime/native/backend changes), `EffectsTestCase`, `FormatterTestCase`, `BabbleModulesTestCase`, `ReplTestCase`, `DifferentialTestCase` (`src/test/babble/Effects.ba`), `-format -check`, and byte-identical `examples/raytracer-argon/scene.ppm`.

### RM003 — JVM Interfaces & Proxy-Free Adapters *(Implemented)*

Lowers Babble interfaces and Java interop adapters from runtime wrappers and `java.lang.reflect.Proxy` objects to native JVM interfaces, direct `implements` bridges, and cached `LambdaMetafactory` SAM adapters across `RM003-P1`–`RM003-P4`. See [bip001_bytecode-compiler.md §20](bip001_bytecode-compiler.md#20-design--implementation-notes-rm003--jvm-interfaces-java-interface-bridges-and-lambdametafactory-sam-adapters) for design and implementation notes.

- **Spans:** [BIP001](bip001_bytecode-compiler.md) (§17, §20), [BIP002](bip002_object-model.md) (§7.3, §9.3, §9.5–§9.6, §12 `BIP002-P6`, §13), [BIP006](bip006_module-sources-and-aot.md) (§9)
- **Depends on:** `RM001` and `BIP006-P4`–`P6`
