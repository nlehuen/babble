# Babble Improvement Proposals (BIPs)

Design documents and language proposals for Babble, numbered chronologically by creation date in the git history.

## Naming convention

Items within each proposal use stable identifiers prefixed by the BIP number:

- **`BIP###-Q#`** — open questions (e.g., `BIP007-Q1`). Resolving a question gives a corresponding decision (`BIP###-D#`).
- **`BIP###-D#`** — decision points (e.g., `BIP001-D1`, `BIP002-D3`). Where a decision settles an earlier question, both are linked (e.g., `BIP005-Q1` → `BIP005-D1`, or `BIP001-Q1` → `BIP003-D1`).
- **`BIP###-P#`** — **planned** features / implementation phases not yet implemented (e.g., `BIP###-P1`, `BIP###-P1`–`BIP###-P3`; sub-phases may carry a letter suffix such as `BIP###-P0a`).
- **`BIP###-I#`** — **implemented** features / implementation phases (e.g., `BIP001-I0`–`BIP001-I4`, `BIP008-I1`–`BIP008-I7`, `BIP008-I6a`).
  - **Transition rule:** Always write full `BIP###-P#` / `BIP###-I#` identifiers (rather than bare `P#` shorthands) so references remain unambiguously searchable and rewritable. When a planned feature `BIP###-P#` is fully implemented, rewrite **all** of its references across the repository (design docs, `AGENTS.md`, `README.md`, code comments, `.ba` and `.batest` files) from `BIP###-P#` to `BIP###-I#` using `src/tools/mark_bip_implemented.py`:
    ```bash
    # Preview changes for one phase or an inclusive range (substitute the BIP number for NNN)
    python3 src/tools/mark_bip_implemented.py --dry-run --diff BIPNNN-P1
    python3 src/tools/mark_bip_implemented.py --dry-run --diff BIPNNN-P1..P3

    # Apply the rewrite across the repository
    python3 src/tools/mark_bip_implemented.py BIPNNN-P1
    python3 src/tools/mark_bip_implemented.py BIPNNN-P1 BIPNNN-P2 BIPNNN-P3

    # List all remaining planned BIP###-P# references in the repository
    python3 src/tools/mark_bip_implemented.py --list-planned
    ```
    The script handles single references (`BIP###-P#`), sub-phases (`BIP###-P#a`), ranges (`BIP###-P1`–`P3`, splitting partial ranges automatically when only a subset is promoted), and comma/slash lists sharing a BIP prefix, while leaving Java class and method identifiers (e.g., `Bip020P1PlainClassesTestCase`) untouched.

Roadmap stages group related work across proposals into sequential milestones:

- **`RM###`** — transversal roadmap stages (e.g., `RM001`, `RM002`). Each `RM` stage bundles multiple BIP items across several topics into a cohesive delivery slice.
  - **Referencing rule:** Outside `docs/design/README.md`, only **past (already implemented)** `RM###` milestones may be mentioned, with the sole exception of a PR or commit description that is directly implementing that `RM###` (e.g., mentioning `RM999` in the PR or commit description implementing `RM999` is fine). Unimplemented `RM###` identifiers must never appear anywhere else — not in code or tests, not in other docs or BIPs (refer to stable `BIP###` / `BIP###-P#` / `BIP###-I#` / `BIP###-D#` identifiers instead), and not in unrelated commit or PR descriptions — so the future part of the roadmap can be modified, merged, split, or reordered at will.

## What is done

### Cross-BIP baseline

With `BIP001-I0`–`BIP001-I3`, `BIP002-I1`–`BIP002-I6`, `BIP004`, `BIP005-I1`–`BIP005-I5`, `BIP006-I1`–`BIP006-I6`, `BIP008-I1`–`BIP008-I7`, `RM001`, `RM002` (`BIP007-I1`), `BIP009-I1`–`BIP009-I4`, `RM003`, `RM004` (`BIP010-I1`–`I6`), `RM005` (`BIP011-I1`–`I6`), `RM006` (`BIP012-I1`–`I4`), `RM007` (`BIP007-I2`–`I3`), `RM008` (`BIP016-I1`–`I4`), `RM009` (`BIP013-I1`–`I4`, `BIP017-I1`–`I3`), and `RM010` (`BIP014-I0`–`I2`) landed, Babble has:

- A shared, `java.base`-only runtime (`BIP001-I0`, `BIP006-I1`) and dual-mode execution (parse-tree `Interpreter` + ANTLR-free `HIR` compiler `HirBuilder` → `PassManager` → `HirEmitter` with `invokedynamic` call/select/Java inline caches).
- Classes, `record` value classes, objects, interfaces with default methods, and two-way Java interop (`BIP002`, lowered in `RM003` to native JVM interfaces, direct Java-interface bridges in compiled mode, and cached `LambdaMetafactory` SAM adapters).
- Nested interactive sessions (`BIP004`), cross-file modules with `ModuleSource` abstractions (`BIP005`, `BIP006-I2`–`I3`), and reproducible AOT jars (`babblec` `-compile`, `BIP006-I4`–`I6`).
- Mandatory static typing (`BIP008`) with `any`/`any?`, `T?`, `A | B`, `?.`, `as`, flow-sensitive narrowing, generics (`of`), call-site parameter inference, and `int`→`double` conversion on numeric joins (`BIP008-D7`), eliminating internal `BIP003-D9` runtime checks.
- Typed primitive lowering & static dispatch (`RM001`): unboxed `int`/`double`/`bool` locals, closure cells (`IntCell`/`DoubleCell`/`BoolCell`), compiled class fields, `$spec` entry points, typed `invokedynamic` calls, direct static Java dispatch, indexed module exports, and cross-classloader primitive field inline caches.
- Core static effect & `axiom` contract layer (`RM002` / `BIP007-I1`): SCC fixed-point inference and verification for `{pure, hermetic, mut, borrow, deterministic, nothrow}`, compositional algebraic properties (`idempotent`, `commutative`, `associative`, `monotone`, `injective`), `@PARAM`/`@THIS` alias tracking and static call-site `mut` exclusivity, frame-local `borrow` closures, bounded call-site higher-order specialization, cross-module `ModuleInterface` & REPL `AnalysisSession` persistence (`BIP007-D2`), and the 7-tier Java host contract layer (`axiom`/`impure`, `org.babblelang.effects`, `BabbleScriptEngine`).
- Systematic differential & coverage harness (`BIP009`): `.batest` multi-module/multi-session specification runner (`61` `.batest` files / `869` cases at `BIP009`, grown to `70` files / `987` cases through `RM009`) with leak-free error normalization and dual-JVM `-Pbatest` JaCoCo coverage reporting across `Interpreter`, `Compiler`, `Shared Front-End`, and `Shared Runtime` (`>= 75%` branch coverage gate).
- JVM interfaces & proxy-free adapters (`RM003`): Babble interfaces compiled to real JVM interfaces (`INVOKEINTERFACE`, `INSTANCEOF`, `INVOKESPECIAL` `super(I).m()`, cross-module/session `ScriptClassLoader` hierarchy), direct Java-interface `implements` clauses and exact-signature overload bridges on compiled Babble classes (retiring `Proxy` faces in compiled mode), and cached `LambdaMetafactory` SAM callback adapters for `0..16`-arg accessible functional interfaces (with `Proxy` fallback only for inaccessible, child-loader, or `>16`-arg SAMs).
- A modular front end (`RM004` / `BIP010`): the 6,828-line `TypeChecker.java` decomposed with zero semantic change into package-private collaborators (`TypeAlgebra`, `CallSolver`, `JavaTypeBridge`, `TypeAnnotations`, `MemberTypes`, `OperatorTypes`, `Narrowing`, `SlotInference`, `LoweringAnalyzer`, `TypedProgram`, `TypedModuleSummary`, `ImportedSummaries`, `StaticRefs`), one `SlotCell` inference engine with a single verification walk, and no retained `TypeChecker` across modules or session inputs.
- Complete core types & Java nullability alignment (`RM005` / `BIP011`): all 9 scalars (`byte`..`char` + transparent `string`) with 8-primitive `RM001`/`RM003` unboxing, 5 zero-wrapper `java.util` collections (`list`..`sortedmap`) + `entry`, mutable generic invariance + `borrow` covariance, `@NotNull`/`@Nullable`/JSpecify + `java.base` parametric nullness + `e!` + defensive Java boundary checks, and built-in `BIP007` effect profiles.
- A predicate-free LL(1)/LL(2) single-bracket `()` grammar & SLL fast path (`RM006` / `BIP012`): zero `@parser::members` and zero semantic predicates in `Babble.g4`, `fn`-first functions, `of` generics across types/`def`/standalone `expr of T`, `on` + reserved effect keywords in `memberName`, mandatory `class` parameters, `record` replacing `value class`, factored `ifExpr`, unified assignment, aligned `as`/`is`/`not` precedence with `is` taking a static `type`, and `PredictionMode.SLL` → `LL` fast path verified across all `.ba` and `.batest` sources.
- Deep ownership, `frozen` types & axiom verification (`RM007` / `BIP007-I2`–`I3`): `unique`/`frozen` tokens (`memberName`-exempted, zero predicates, pure `SLL`), covariant `Type.Frozen` preserving `frozen` under `is` narrowing (`BIP007-D7`), zero-cost `move(x)`/`freeze(expr)`/`discard(expr)` built-ins, `@Unique` Java annotation, full `unique`/`@MOVED` ownership lattice (enabling fresh local and `RM005` core-collection mutation inside `pure` functions, `BIP007-D6`), `@TERMINATING` SCC inference, unused `pure nothrow` compile errors (`BIP007-D8`), opt-in ASM `BytecodeEffectAnalyzer`, and `babble.checkAxioms` property-based axiom fuzzing (`AxiomChecker`).
- Consolidated pure-by-default effect surface syntax & return-through-borrow (`RM008` / `BIP016-D1`–`D10`, `BIP016-I1`–`I4`): decouples `BIP007`'s internal orthogonal `@TRAITS` from a closed opt-out vocabulary (`io`, `volatile`, `mut`, `shared`, `unique`, opt-in `nothrow`, `axiom pure`), defaults typed `fn`s/`export`s/`interface`s/function types to `{@HERMETIC, @DETERMINISTIC, @CONST, @BORROWED}` while keeping inference on completely untyped inline lambdas, allows `@BORROWED` parameters to return without viral `shared` via return-origin provenance (`BIP016-D10`), aligns `org.babblelang.effects` (`@Pure`/`@Volatile`/`@Shared`/`@IO`), and reduces Argon from `439 → 28` effect tokens (`−93.6%`).
- First-class iterators, loop control & higher-order function effect forwarding (`RM009` / `BIP013-I1`–`I4`, `BIP017-I1`–`I3`): `for <var> [: <type>] in <iterable> then (...)` expressions across `JavaArray`, `java.lang.Iterable`, bare `java.util.Iterator`, Babble custom iterables/iterators (`$spec` unboxed dispatch), and unions; uniform `break [expr]` / `continue` across `while` and `for` loops; parameterized static factories `(list of int).of(...)` / `list.of(...)`; and `fn calling f` / `fn calling (f, g)` callback-effect forwarding across concrete functions, cross-module `TypedModuleSummary`, `interface` methods, and first-class values (forwarding `io`/`volatile`/`nothrow`/`@TERMINATING`, frame-local closures, and bound mutating methods `buf.append`, while retiring `BIP016-D6`'s implicit intra-file `fn io` HOF specialization).
- ANTLR-free `HIR` compiler & Nanopass optimizer (`RM010` / `BIP014-I0`–`I2`): decomposed the legacy 6,269-line `CodeGenerator.java` into `ScriptClassWriter`/`ConstantPool`/`InterfaceGen`/`ClassGen` + `org.babblelang.ir.hir` (`HirModule`, 44-variant `HirExpr`, `HirBuilder`, `HirVerifier`, `HirPrinter`) + `HirEmitter`, and enabled the `-O1` Nanopass pipeline (`ConstFoldPass`, `AlgebraicSimplifyPass`, `InlinePass` with intra-module + `babblec`-only AOT cross-module small-export inlining, `HirDcePass`, structured `HirLicmPass`) by default with 3-way `interpret` / `-O1` / `-O0` CI parity (`compiled-tests-O0` in `pom.xml`, `-O0`/`-O1`/`-O2` CLI flags, `-Dbabble.dumpIr`).

## Roadmap

The stages below sequence what remains of the BIPs that are not fully implemented — `BIP014-P3`–`P5`, `BIP015` (`BIP015-Q1`–`Q8`), `BIP018-P0`–`P4`, `BIP025-P0`–`P5`, and `BIP026-P1`–`P5` — into **transversal milestones** `RM011`–`RM017`, each keeping `mvn package` green in all three modes (`interpret`, `compile -O1`, `compile -O0`). Work that no BIP specifies yet is listed in the [backlog](#backlog-awaiting-a-bip) at the end: a milestone that needs one of those items starts by writing its BIP.

The order follows the constraints the BIPs record :

- **Decided and small first.** `BIP022-I2` has landed and `BIP026-P1` only needs `BIP026-Q1`–`Q3` and touches nothing but the lexer's string rules.
- **Measure, then optimize.** `BIP014` §9.1 found that the ray tracers' hot loops are dominated by short-lived `record` allocations (`record Vec3` dot loop : `6.09 ms` vs. `0.48 ms` for the scalar loop), so `BIP014-P4` (`record` method inlining, `ScalarReplacePass`) comes before the general SSA `MIR` of `BIP014-P3`.
- **Choose the parser before the largest grammar change.** `BIP026-P2` splits `Babble.g4` into lexer modes; `BIP015-Q3` asks whether a parser transition should precede new syntax, so `BIP015` is settled first.
- **`BIP018` after `BIP014`.** `BIP018-D4` starts all of `BIP018` once `BIP014` completes, that is after `BIP014-P5`.

### RM011 — Intersection Types & Multiline Strings

Finishes intersection types and gives Babble multiline and raw string literals, two decided or nearly decided slices that need no other milestone.

- **Spans:** [BIP022](bip022_intersection-types.md) (§8, `BIP022-D4`, `BIP022-D6`–`D8`), [BIP026](bip026_multiline-strings-and-string-templates.md) (§3.1, §5.2–§5.4, `BIP026-Q1`–`Q3`), [BIP012](bip012_grammar-improvements.md) (pure `SLL` grammar), [BIP021](bip021_optional-variadic-overloaded-arguments.md) (bounds and overload sets)
- **Depends on:** nothing pending (`BIP022-I1`, `BIP021-I3` and `BIP021-I5` have landed).
- **Deliverables:**
  - *`BIP022-I2` — Java, dispatch and overload sets (landed):* Java type variables with several bounds (translated to their intersection with F-bound cycle guards rather than `any?`), eager Java SAM and SAM+marker adapter conversion (`Runnable` / `Runnable & Serializable`, `BIP022-D7`, isolated to Java-interop HIR/runtime nodes using `FLAG_MARKERS`), direct chained `INSTANCEOF` lowering for `is A & B` (`BIP022-D6`), lazy member-conflict and covariant signature rules (`BIP022-D4`) with most-specific interface dispatch, and meets/union splits in `BIP021` overload sets (`BIP022-D8`).
  - *`BIP026-P1` — multiline & raw strings:* deciding `BIP026-Q1`–`Q3`, then `"""..."""` with compile-time dedenting, raw `r"..."` / `r"""..."""`, the shared dedenter/unescaper used by `Interpreter` and `HirBuilder`, `Formatter` rules and `BabbleSession.classify` for unfinished literals.
- **Exit criteria:** `BIP022` §10 tests and `.batest` specs in three modes; `src/test/babble/MultilineStrings.ba`, `FormatterTestCase` round-trips, `ReplTestCase` multi-line inputs, and `ParserGrammarTestCase` pure `SLL`.

### RM013 — Front-End Decision & String Templates

Settles [BIP015](bip015_down-with-the-ants.md) (*Down with the ants*) before the largest grammar change on the horizon, then lands string templates on the chosen front end.

- **Spans:** [BIP015](bip015_down-with-the-ants.md) (`BIP015-Q1`–`Q8`), [BIP026](bip026_multiline-strings-and-string-templates.md) (`BIP026-Q4`–`Q10`, §3.2–§6), [BIP012](bip012_grammar-improvements.md), [BIP016](bip016_consolidating-effect-annotations.md) / [BIP017](bip017_higher-order-function-effects.md) (effect-qualified templates), [BIP019](bip019_refactoring-axioms.md) (`template` axioms), [BIP014](bip014_optimization-passes.md) (`-O1` deforestation), [BIP009](bip009_test-coverage.md)
- **Depends on:** `RM011` (`BIP026-P1`). The decision step is design work and can start at any time.
- **Decision step first:** settle `BIP015-Q1`–`Q8` into `BIP015-D1`–`D8`: keep ANTLR4, put a Babble-owned sealed-record AST behind it, or replace it (hand-written recursive descent + Pratt, or another option of §4). If a migration is chosen, it lands first, with 100% parse and `BabbleSession.classify` parity across all `.ba` and `.batest` sources, so that `BIP026-P2` is written once against the new front end.
- **Deliverables:**
  - *`BIP026-P2` — template syntax:* lexer modes with a paren-depth stack (split ANTLR4 grammar, or the hand-written lexer), `t"..."`, `t"""..."""`, `rt"..."`, multi-dollar `t$$"""..."""` and `$(expr)`, with `Formatter` and `classify` support.
  - *`BIP026-P3`–`P4` — runtime and policies:* `java.base`-only `Template` / `Placeholder` with lazy memoization, `template` / `placeholder` core types, lowering in both backends, `TemplatePolicy of R` and `tmpl.eval(policy)`, and effect tracking (`BIP026-Q8`).
  - *`BIP026-P5` — deforestation:* constant template folding and direct `.render()` lowering to `StringConcatFactory` at `-O1`.
- **Exit criteria:** `ParserGrammarTestCase`, `RuntimeBoundaryTestCase`, `AxiomsTestCase`, `EffectsTestCase`, template `.batest` specs in three modes, `OptimizerTestCase` (no `Template` allocation on direct `.render()`), and `-Pbatest` (`>= 75%` branch gate, extended to the parser if ANTLR4 is removed, `BIP015-Q8`).

### RM015 — `Babble 21` & `Babble 25` Editions

Begins [BIP018](bip018_tracking-java-improvements.md) once `BIP014` is complete (`BIP018-D4`): a multi-JDK CI matrix, the monorepo split, and a `Babble 25` edition without ASM.

### RM016 — Verified Parallelism, `Babble 28` & Valhalla

Makes Babble safe to run on several threads in both backends, adds effect-verified parallel combinators, and backs them with structured concurrency and value classes on newer JDKs.

- **Spans:** [BIP007](bip007_effects.md) (§10), [BIP018](bip018_tracking-java-improvements.md) (`BIP018-P3`–`P4`), [BIP016](bip016_consolidating-effect-annotations.md), [BIP011](bip011_core-types.md) (`frozen` core collections), [BIP002](bip002_object-model.md) / [BIP020](bip020_array-types.md) (`record`s as JVM value classes, `BIP020-D18`), [AGENTS.md](../../AGENTS.md) (known issue: the single-threaded `Interpreter`)
- **Depends on:** `RM015`, `std/...` (`RM014`), and a parallelism BIP specifying the `threadsafe` effect and the parallel combinators ([backlog](#backlog-awaiting-a-bip)). Making the `Interpreter` thread-safe is independent and can land at any point.
- **Deliverables:**
  - *Thread-safe `Interpreter`:* no mutable current-scope field, runtime caches (`Bootstrap`, `Overloads`, `Modules`) audited under concurrency, multi-threaded tests in all modes, and `examples/raytracer-fable` running interpreted.
  - *`threadsafe` & parallel `std/` (`BIP007` §10):* `parallelMap`, `parallelFilter`, `parallelReduce` (`associative`, plus `commutative` for work-stealing) and `parallelForEach` over `frozen` / `unique` inputs.
  - *`BIP018-P3`:* `babble-runtime-jdk28` backing the combinators with `StructuredTaskScope`, and `babble-28`, with Leyden AOT code compilation benchmarks.

- **Exit criteria:** multi-threaded `DifferentialTestCase` / `BatestTestCase` coverage, race-freedom checks on the parallel combinators, and `examples/raytracer-argon` allocation and throughput benchmarks on `babble-21`, `babble-25` and `babble-28-preview`.
